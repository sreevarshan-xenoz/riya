# Riya v0.1: rulings made during autopilot execution (2026-10-18)

Every decision taken on the user's behalf while executing the three plans. Each line: what was decided — why — what it costs if wrong.

## core plan

- Ruling: work on feature branch feat/riya-v0.1 in the main checkout instead of a separate worktree — untracked runtime assets (riya images/, riya_memory.json, scratch_runs/) live here and the user asked for autopilot — cost if wrong: main checkout sits on the feature branch until merge; trivially switchable.
- Ruling: T10 schema file is written by Python with utf-8 (e.g. `python -m riya.core.protocol --write docs/protocol.schema.json` or equivalent), not a shell redirect — PowerShell `>` writes UTF-16 and would break the contract test — cost if wrong: none.
- Ruling: T1 appends only the .gitignore lines not already present — avoids duplicates — cost if wrong: cosmetic.
- Ruling: new looked_up fact vs old inferred fact on same key → both conflict (brief silent; only user_said supersedes) — keeps both visible per spec "contradictions stay visible" — cost if wrong: a looked-up fact doesn't auto-win over an inference; user can resolve.
- Ruling: T2 tokenizer uses Unicode-aware \w+ on casefolded text instead of plan's [a-z0-9]+ — plan's regex makes non-English facts collide as duplicates, violating the spec's honesty/emoji+non-English review focus — cost if wrong: none (hash embedder is test/dev only).
- Ruling: T2 forgotten markers block only non-user_said proposals (inferred/looked_up); an explicit user_said statement is always stored — spec: explicit statements outrank inferences; forgetting exists to stop consolidation resurrecting facts — cost if wrong: user can re-delete.
- Ruling: T2 delete_fact deletes the whole supersession chain (every version) and leaves a forgotten marker per deleted version — spec §6.4 "deleting is a real delete" — cost if wrong: history of a deleted fact is gone (intended).
- Ruling: T2 correct() on a non-active (superseded) fact raises ValueError; an explicit user_said fact or correction supersedes all active AND conflict facts with the same key — keeps one source of truth per key — cost if wrong: caller must pass the chain head.
- Ruling: T2 multi-statement writes run in one transaction (`with self.db:`), source validated against RANK; similarity skips stored embeddings whose dim differs from the current embedder — avoids half-applied writes and a crash when switching embedders — cost if wrong: none.
- Ruling: (supersedes earlier looked_up ruling) RANK ordering applies: looked_up supersedes inferred on the same key; equal rank → conflict — consistent with spec 'explicit statements outrank inferences' — cost if wrong: a looked-up fact silently replaces an inference (history kept).
- Ruling: T2 delete_fact's chain = supersedes_id links (both directions) PLUS every superseded row sharing a non-null key with any chain member — the schema links only one predecessor, and deleting the current value of a key must remove all its older values — cost if wrong: deleting the current value also erases older superseded values of that key (intended for "real delete").
- Ruling: HashEmbedder default dim 512 → 2048 (T3) — bigram hash collision made the brief's never-said retrieval test fail at 512; hash embedder is test/dev only — cost if wrong: none.
- Ruling: T4 Feelings is self-contained (no AffectCore reuse), porting only chat.py's energy/fatigue logic — brief's bounded-change and exact round-trip contracts are easier to guarantee; jarvis/ stays the research track — cost if wrong: research affect dynamics (drives/learning progress) aren't wired into the product yet; can be layered later.
- Ruling: T4 mood = slow average of valence integrated step-size-independently (mood relaxes toward the pre-decay valence, closed form per tick) plus a slow reversion to a baseline mood (0.1) with a 3-day time constant — spec §6.3 "slow average over hours to days"; avoids permanent ratchet — cost if wrong: mood recovers on its own over days.
- Ruling: consolidation-proposed facts are checked against forgotten markers regardless of source (Memory.add_fact gains keyword-only check_forgotten; Consolidator passes True) — a model's reading of an old transcript isn't a live explicit statement, and the brief's own test expects a deleted user_said fact not to return via consolidation — cost if wrong: a fact the user re-states in a later conversation is only re-stored when said live (remember-that path or new user_said).
- Ruling: T8 work_stretch resets when input resumes from a break (start of the 60 s tail), not at break_ended — the brief's own test requires it; difference is ≤60 s — cost if wrong: work stretch under-counts by up to a minute.
- Ruling: (for T11) a coming-home greeting is never spoken while presence is "gaming": if the user comes back straight into a fullscreen app, the greeting is deferred until the first tick that is not gaming, and dropped if that takes longer than 30 min — spec §6.8 "never while gaming or fullscreen" — cost if wrong: a gamer who returns straight into a game gets a delayed or no greeting.
- Ruling: (for T11) RiyaCore.reply/speak_first/tick never raise out to callers: if the model fails before or during a reply (e.g. llama-server down → ModelUnavailable or any exception), the engine logs it, emits ErrorMsg("Riya's local model isn't responding") plus SayEnd for the open utterance, records nothing for the assistant turn, and returns — anti-goal "she stops working" — cost if wrong: a silent turn instead of a crash.
- Ruling: T11 judgment calls accepted — deferred greeting also defers feelings.on_return (dropped greeting ⇒ no on_return); tick uses non-blocking lock acquire and skips a whole tick while a reply/greeting holds it; muted greeting not marked spoken; 600 s gap between consolidation attempts; bids recorded as assistant transcript; handle() doesn't take the reply lock — keeps the 1 s loop and memory panel responsive during TTS — cost if wrong: presence events are delayed by the length of a spoken reply.
- Ruling: T11 greeting thread is marked followed_up only after the greeting was actually generated (plan said mark first) — otherwise a model outage silently loses the follow-up — cost if wrong: none.
- Ruling: T11 tick steps are isolated (each step has its own try/log) so one failing step can't starve consolidation/purge/persistence — cost if wrong: none.
- Ruling: T11 StateMsg cadence uses its own 30 s timer, independent of feelings persistence — the body needs regular state while chatting — cost if wrong: none.
- Ruling: T11 a reply closed early (barge-in → generator close) still records the user turn and the partial assistant text said so far — keeps context for the next turn — cost if wrong: the transcript holds a cut-off reply.
- Ruling: T11 a greeting cut off by barge-in sets only raised_at and leaves the thread open (24 h cooldown prevents a repeat today) — she may not have asked yet — cost if wrong: the follow-up can recur the next day.
- Ruling: (for T13) the WS receive loop handles non-UserText messages without waiting behind an in-flight reply (UserText replies run as a background task per socket, serialized among themselves by the engine lock) so talk_hotkey/settings/memory edits stay responsive — cost if wrong: messages from one socket may be processed out of order relative to a running reply (acceptable).
- Ruling: T13 a silent bid opens the listen gate for the normal 2-min window so a spoken answer works without her name — spec §6.7 lists "a bid that gets answered" as a conversation start — cost if wrong: background speech within 2 min of a bid could reach her.
- Ruling: T13 old `python -m riya.voice` CLI (drove riya.chat.Riya) is retired; voice runs via `python -m riya.core` — single runtime — cost if wrong: the old standalone CLI is gone (riya.chat text CLI remains).
- Ruling: T13 barge-in arms once her audio starts; speech during generation becomes the next turn — cost if wrong: can't cancel a reply before it starts speaking.
- Ruling: retrieval eligibility becomes embedder-aware and hybrid (fixes production honesty gap found in T14): each embedder exposes `strong_sim` and `weak_sim` (HashEmbedder 0.2/0.2; FastEmbedder bge-small 0.80/0.60); a fact or episode is eligible if sim >= strong_sim, or sim >= weak_sim AND it shares >= 1 content token (tokenize() minus STOPWORDS) with the query. Memory(min_sim=...) stays as an explicit override for both thresholds — bge never-said questions score 0.50-0.70 while hits are >= 0.71, so a bare cosine cutoff can't separate them; lexical evidence can — cost if wrong: a pure-paraphrase question with no shared words and bge sim < 0.80 won't retrieve its memory (she says she doesn't remember).
- Ruling: final fix wave follows final-findings.md exactly (each item's RULING is binding) — see that file for per-item decisions — cost if wrong: per item, listed in the user summary.
- Ruling: C4 uses an Origin allowlist (absent, "null", "file://") instead of a per-install token — no body change needed and blocks browser pages — cost if wrong: a local non-browser process could still connect (same trust as the user account).
- Ruling: remember-that facts stay keyless; with I4 a later contradictory "remember…" is stored alongside (newer wins by recency in retrieval) rather than superseding — cost if wrong: two dated versions visible until consolidation/user correction.
- Ruling: (parked) I7 model outages count toward the 3-failure cap as ruled — a ~30 min llama-server outage turns that chunk into "summary unavailable" — accepted for v0.1 (outages rare; transcript still kept 30 days) — cost if wrong: one conversation's summary lost after a long outage; one-line change to count only unusable replies.
- Ruling: I1 came_back consolidation uses the local model even when online_consolidation is on — keeps the greeting path offline-safe — cost if wrong: slightly worse summary for that one chunk.
- Ruling: KV shares the memory lock (beyond ruling) — accepted; lock order core→memory everywhere.
- Ruling: (parked, load-bearing → surface to user at finish) N1 about-me regex ("tell me what you remember about X") switches to recency-only top-8 and can drop the fact about X, after which HONESTY_LINE tells her to deny it — smallest fix: in about-me mode put similarity-eligible facts first, fill to 8 by quality/recency, and tie the "tell me … you remember" branch to "about me"/end of sentence — no second fix wave per process — cost if wrong: for >8 facts that phrasing can make her deny a memory she has.
- Ruling: (parked, surface to user) negations dedupe as duplicates because "not"/"no" are STOPWORDS ("is vegetarian" vs "is not vegetarian" → second dropped) — fix: remove negation words from STOPWORDS (or treat them as content tokens in the dup check) — cost if wrong: a negated correction stated via remember-that is lost.

## body plan

- Ruling: keep Electron pinned at 33.2.1 (plan) despite npm audit advisories, and require hardened windows (contextIsolation: true, nodeIntegration: false, sandbox where possible, no remote content, navigation blocked) in Task 3 — the app only loads local files and talks to localhost — cost if wrong: known Electron CVEs remain reachable only via local content; upgrade later.
- Ruling: sprite manifest schema stays closed (additionalProperties:false); the sprites-plan builder must omit absent frames and keep its missing-frames list outside manifest.json (returned/printed only) — strict contract catches typos — cost if wrong: builder metadata needs a schema change later.
- Ruling: (for T3/T4) frame paths from a manifest are resolved inside the pack directory only; any path escaping it (../, absolute) is treated as missing and falls back — untrusted pack content — cost if wrong: none.
- Ruling: talk hotkey tries Control+Alt+Space first; if registration fails (taken by another app on this machine), fall back to Control+Alt+F9 and log which one is active (settings page shows it in T5) — plan value is occupied here — cost if wrong: a different chord than planned.
- Ruling: the single WebSocket lives in a hidden sandboxed bridge window (Electron 33 main has no global WebSocket) — no new dependency — cost if wrong: one extra hidden renderer process.
- Ruling: (for T4) the core emits no expression for a silent bid; the body shows "curious" for the bid bubble's lifetime unless the core sends an expression meanwhile — spec: bid = bubble + expression — cost if wrong: a different expression than ideal.
- Ruling: (for T5) the memory page also lists episodes (with delete → episode_delete) and open threads (with resolve → thread_resolve), added to the protocol by the core final fix wave (I8); the settings page shows the active talk hotkey — spec §6.4/§9 inspect+delete all memory — cost if wrong: none.
- Ruling: body final fix wave follows final-findings.md (C1, I1-I4, M1-M7 included; M8-M11 deferred) — see file — cost if wrong: per item.
- Ruling: correction to core ledger C4 rationale — Electron loadFile pages send Origin "file://", not "null"; "null" is removed from the allowlist (C1).
- Ruling: (parked) I1 idle CPU 6.5–8.8% vs ~5% target (from ~30%) — accepted for v0.1; one-constant follow-up (≈8 Hz timer or 0.2 px rounding → ≈3%) — no second fix wave per process — cost if wrong: ~2–4% extra idle CPU.
