# Riya: rulings made during autopilot execution

Every decision taken on the user's behalf while executing the three plans. Each line: what was decided — why — what it costs if wrong.

## core plan

- Ruling: work on feature branch feat/riya-v0.1 in the main checkout instead of a separate worktree — untracked runtime assets (riya images/, riya_memory.json, scratch_runs/) live here and the user asked for autopilot — cost if wrong: main checkout sits on the feature branch until merge; trivially switchable.
- Ruling: T10 schema file is written by Python with utf-8 (e.g. `python -m riya.core.protocol --write docs/protocol.schema.json` or equivalent), not a shell redirect — PowerShell `>` writes UTF-16 and would break the contract test — cost if wrong: none.
- Ruling: T1 appends only the .gitignore lines not already present — avoids duplicates — cost if wrong: cosmetic.
- Ruling: new looked_up fact vs old inferred fact on same key → both conflict (brief silent; only user_said supersedes) — keeps both visible per spec "contradictions stay visible" — cost if wrong: a looked-up fact doesn't auto-win over an inference; user can resolve.
- Ruling: T2 tokenizer uses Unicode-aware \w+ on casefolded text instead of plan's [a-z0-9]+ — plan's regex makes non-English facts collide as duplicates, violating the spec's honesty/emoji+non-English review focus — cost if wrong: none (hash embedder is test/dev only).
- Ruling: T2 forgotten markers block only non-user_said proposals (inferred/looked_up); an explicit user_said statement is always stored — spec: explicit statements outrank inferences; forgetting exists to stop consolidation resurrecting facts — cost if wrong: user can re-delete.
- Ruling: T2 delete_fact deletes the whole supersession chain (every version) and leaves a forgotten marker per deleted version — spec §6.4 "deleting is a real delete" — cost if wrong: history of a deleted fact is gone (intended).
- Ruling: T2 correct() on a non-active (superseded) fact raises ValueError; an explicit user_said fact or correction supersedes all active AND conflict facts with the same key — keeps one source of truth per key — cost if wrong: caller must pass the chain head.
- Ruling: T2 multi-statement writes run in one transaction (`with self.db:`), source validated against RANK; similarity skips stored embeddings whose dim differs from the current embedder — avoids half-applied writes and a crash when switching embedders — cost if wrong: none.
- Ruling: (supersedes earlier looked_up ruling) RANK ordering applies: looked_up supersedes inferred on the same key; equal rank → conflict — consistent with spec 'explicit statements outrank inferences' — cost if wrong: a looked-up fact silently replaces an inference (history kept).
- Ruling: T2 delete_fact's chain = supersedes_id links (both directions) PLUS every superseded row sharing a non-null key with any chain member — the schema links only one predecessor, and deleting the current value of a key must remove all its older values — cost if wrong: deleting the current value also erases older superseded values of that key (intended for "real delete").
- Ruling: HashEmbedder default dim 512 → 2048 (T3) — bigram hash collision made the brief's never-said retrieval test fail at 512; hash embedder is test/dev only — cost if wrong: none.
- Ruling: T4 Feelings is self-contained (no AffectCore reuse), porting only chat.py's energy/fatigue logic — brief's bounded-change and exact round-trip contracts are easier to guarantee; jarvis/ stays the research track — cost if wrong: research affect dynamics (drives/learning progress) aren't wired into the product yet; can be layered later.
- Ruling: T4 mood = slow average of valence integrated step-size-independently (mood relaxes toward the pre-decay valence, closed form per tick) plus a slow reversion to a baseline mood (0.1) with a 3-day time constant — spec §6.3 "slow average over hours to days"; avoids permanent ratchet — cost if wrong: mood recovers on its own over days.
- Ruling: consolidation-proposed facts are checked against forgotten markers regardless of source (Memory.add_fact gains keyword-only check_forgotten; Consolidator passes True) — a model's reading of an old transcript isn't a live explicit statement, and the brief's own test expects a deleted user_said fact not to return via consolidation — cost if wrong: a fact the user re-states in a later conversation is only re-stored when said live (remember-that path or new user_said).
- Ruling: T8 work_stretch resets when input resumes from a break (start of the 60 s tail), not at break_ended — the brief's own test requires it; difference is ≤60 s — cost if wrong: work stretch under-counts by up to a minute.
- Ruling: (for T11) a coming-home greeting is never spoken while presence is "gaming": if the user comes back straight into a fullscreen app, the greeting is deferred until the first tick that is not gaming, and dropped if that takes longer than 30 min — spec §6.8 "never while gaming or fullscreen" — cost if wrong: a gamer who returns straight into a game gets a delayed or no greeting.
- Ruling: (for T11) RiyaCore.reply/speak_first/tick never raise out to callers: if the model fails before or during a reply (e.g. llama-server down → ModelUnavailable or any exception), the engine logs it, emits ErrorMsg("Riya's local model isn't responding") plus SayEnd for the open utterance, records nothing for the assistant turn, and returns — anti-goal "she stops working" — cost if wrong: a silent turn instead of a crash.
- Ruling: T11 judgment calls accepted — deferred greeting also defers feelings.on_return (dropped greeting ⇒ no on_return); tick uses non-blocking lock acquire and skips a whole tick while a reply/greeting holds it; muted greeting not marked spoken; 600 s gap between consolidation attempts; bids recorded as assistant transcript; handle() doesn't take the reply lock — keeps the 1 s loop and memory panel responsive during TTS — cost if wrong: presence events are delayed by the length of a spoken reply.

- Ruling: T11 tick steps are isolated (each step has its own try/log) so one failing step can't starve consolidation/purge/persistence — cost if wrong: none.

- Ruling: retrieval eligibility becomes embedder-aware and hybrid (fixes production honesty gap found in T14): each embedder exposes `strong_sim` and `weak_sim` (HashEmbedder 0.2/0.2; FastEmbedder bge-small 0.80/0.60); a fact or episode is eligible if sim >= strong_sim, or sim >= weak_sim AND it shares >= 1 content token (tokenize() minus STOPWORDS) with the query.
