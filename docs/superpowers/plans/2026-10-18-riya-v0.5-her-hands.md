# Riya v0.5 "Her hands" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Riya does small things for the user under permission tiers. That covers timers, reminders, notes, time,
weather, lookups, sites, apps, media, volume, the clipboard, named commands and files in her folder. Each risky action
needs a confirmation that only the user's own turn can answer.

**Architecture:**
- A new package `riya/core/hands/`, with these modules:
  - `types.py`: the leaf types `Call`, `ParamSpec` and `ToolResult` (it imports nothing from `riya`).
  - `intent.py`: pure parsing.
  - `safe.py`: calc, URL and file names.
  - `tools.py`: the registry, `validate_call` and the runs (it re-exports the `types.py` names).
  - `policy.py`: decide and confirmations.
  - `effects.py`: the OS, plus FakeEffects.
  - `net.py`: Open-Meteo and Wikipedia, plus FakeHttp.
  - `records.py`: the v3 tables.
  - `reminders.py`: pure delivery.
  - `online.py`: function calling.
- The engine routes user turns to tools in `reply()`. Every call, matched or online, goes through `validate_call`
  before the policy, and the validated call is the snapshot that every later step uses. The engine delivers reminders,
  command results and parked confirmations in `tick()`, and takes button answers in `handle()`.
- The protocol and the body gain the confirm, reminders, actions and notes messages.

**Tech Stack:** Python 3.12 stdlib (`ast`, `zoneinfo`, `ctypes`, `subprocess`, `urllib`), pydantic, pytest; Electron
with `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-18-riya-v0.5-her-hands-design.md`

## Global Constraints
- **Tiers:**
  - T0: `time_now`, `timer_set`, `reminder_set`, `reminder_list`, `reminder_cancel`, `note_add`, `note_list`, `calc`,
    `weather`, `lookup`.
  - T1: `open_url`, `open_app`, `media`, `volume`, `clipboard_copy`.
  - T2: `run_command`, `write_file`.
  - T3 has no code path. Shell, deleting or moving files, messages or email, purchases and credentials get a kind
    refusal.
- **Defaults:**
  - Every tool is on except `run_command` and `write_file`.
  - `hands_online` is true and `weather_place` is None.
  - `apps`, `commands` and `tools_ask` are empty.
  - Only T1 tools may be in `tools_ask`. T2 always asks.
- **Confirmation:**
  - It expires after 60 s. A parked T2 call expires after 10 min.
  - Only one is pending at a time, and a newer one replaces it.
  - What a "yes" runs is the validated call captured when she asked (for `run_command`: the argv, cwd and timeout from
    the settings at that moment). Editing a command afterwards doesn't change it.
- **Timeouts:** network requests (the tools and the online function call) get 8 s. `run_command` gets 60 s, and a
  command's `timeout_s` is clamped to 1–60.
- **Caps:**
  - `ToolResult.text` ≤ 200 chars.
  - The command output tail ≤ 200 chars, after the v0.4 `redact`.
  - 50 active reminders.
  - `write_file` text ≤ 64 KB (65,536 UTF-8 bytes).
  - The action log is purged after 30 days.
- **Network:** User-Agent `Riya/0.5 (personal desktop companion)`. Weather sends only the place; lookup sends only the
  query.
- **Media:** "volume up/down" is 5 presses, and mute is 1. Keys go through `SendInput` with `KEYEVENTF_EXTENDEDKEY`.
- **Command-form triggers:** open, launch, play, pause, set, remind, start, turn, mute, copy, save, write, run, check,
  look up, search, find. The trigger comes first, or after "can/could/would you" or "please".
- **Yes and no forms:** the whole turn, ignoring punctuation and a leading "riya".
  - Yes: "yes", "yeah", "do it", "go ahead", "sure", "ok", "okay".
  - No: "no", "nope", "nah", "don't", "cancel", "stop", "no thanks".
- **Only the user's current turn acts:**
  - Screen notes, agent payloads, web text, her replies and memories never reach `match`, the online call or a
    confirmation.
  - Named commands run `subprocess.run(argv, shell=False)` from the stored argv only.
  - The online model is used only when `settings.online_enabled` is on as well as `hands_online`.
- **Template wording:** templates quote names with `"…"`, never `*…*` (`shaping.tts_text` strips stage directions).
  The confirmation is `Run "backup" (<argv joined>)? (yes / no)`.
- **Tests:**
  - They never open apps, URLs or windows, never send real keys and never run real commands. Use `FakeEffects`; a
    `WindowsEffects` test monkeypatches `os.startfile`, `SendInput` and `subprocess.run`.
  - The network is always faked (`FakeHttp`, or a monkeypatched `urlopen`).
  - `make_core` gives each core a temporary `riya_dir`.
- **Never run the Claude Code hooks installer.**
- **Protocol schema:** `python -m riya.core.protocol --write docs/protocol.schema.json`, never a shell redirect.
- **Commit trailer:** end every commit message with exactly these two lines:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01BiCkE9KiCaYfkY6JzGzsZx`.
- **Everything green stays green:** `.venv\Scripts\python -m pytest -q` and `cd body && npm test`, after every task.

## Review Focus
1. **"Remind me at 5" said at 17:30.** It's due at 05:00 tomorrow, and it's never refused. Test: Task 1
   `test_at_5_after_1730_is_5am_tomorrow`.
2. **A DST change, or sleep across a due time.**
   - Wall-clock times keep their local hour. "In 2 hours" is elapsed time.
   - A jump past `due_at` fires exactly once, with "(this was due at …)".
   - Tests: Task 1 `test_tomorrow_at_9_across_spring_forward`, Task 8 `test_sleep_past_due_fires_once_with_note` and
     `test_dst_reminder_fires_at_local_9`.
3. **An injected "open evil.com"** in a screen note, an agent payload, a memory or her own reply never runs and never
   reaches the online model. Tests: Task 7 `test_injected_open_never_runs` and
   `test_online_request_carries_only_the_turn`.
4. **A confirmation answered after it expired or was replaced.**
   - Nothing runs.
   - A late "yes" gets the templated timed-out line.
   - A stale button gets `confirm_done` "expired" or "replaced".
   - Tests: Task 3 `test_expiry_and_replacement`, Task 7 `test_yes_after_expiry_runs_nothing` and
     `test_button_for_replaced_confirmation_runs_nothing`.
5. **A reminder due in quiet hours, with `may_start_conversations` off, or while gaming.** It's a bubble at once,
   marked fired, never spoken and never dropped. Tests: Task 5 `test_delivery_table`, Task 8
   `test_reminder_in_quiet_hours_or_gaming_is_a_bubble` and `test_reminder_due_on_greeting_tick`.
