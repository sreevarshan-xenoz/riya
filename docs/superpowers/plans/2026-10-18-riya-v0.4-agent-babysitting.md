# Riya v0.4 "Agent babysitting" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Riya knows what the user's Claude Code sessions and Colab runs are doing, reports finishes, failures and
approval requests with good manners, shows them in her agents area, and plays small games with the user while agents
run.

**Architecture:**
- A new package `riya/agents/` with four modules:
  - `hub.py`: a pure state machine producing AgentEvents and snapshots.
  - `hooks.py`: a FastAPI receiver on 127.0.0.1:8766 with a shared-secret token.
  - `logwatch.py`: an incremental log tailer for Colab runs.
  - `install_hooks.py`: a reversible settings installer.
- The engine consumes AgentEvents through a report queue.
- `riya/core/games.py` adds word chain, 20 questions and riddles.
- The protocol gains `agents`, and the body renders it.

**Spec:** `docs/superpowers/specs/2026-10-18-riya-v0.4-agent-babysitting-design.md`

## Global Constraints
- **Hook receiver:**
  - It binds `127.0.0.1:8766` only.
  - The `X-Riya-Token` header must equal `%LOCALAPPDATA%/Riya/hook_token` (32 random bytes in hex, created on first run,
    with permissions left at user-only defaults). A missing or wrong token gets 401.
  - Any `Origin` header gets 403. A body over 256 KB gets 413.
  - Valid requests get 200 with an empty body, always within about 50 ms. The work is enqueued, never done inline.
  - Malformed JSON with a valid token still gets 200 and nothing is enqueued.
- **Claude state machine** (spec §4.2): busy goes to `unknown` after 30 min with no events; ended agents are removed 10
  min after SessionEnd; 3 tool failures in one turn count as failed.
- **Colab logwatch:**
  - It polls every 60 s.
  - The default entry is `{name: "colab", glob: "G:/My Drive/jarvis/runs/**/*.out", done_re:
    "STAGE0_TRAIN_DONE|ROLE_DONE|BENCH_DONE|GEN_DONE|TRAIN_DONE|PASS1_DONE", fail_re: "FAILED|Traceback", lost_re:
    "LOST"}`.
  - A run counts as stalled after 30 min with no growth while running.
- **Report manners:**
  - Urgent kinds are failed, waiting, lost and stalled. They're spoken now when the user is focused or talking, shown as
    a bubble only while gaming, and delivered on return when the user is away.
  - Finished is delivered on the next break, talking turn or greeting.
  - At most 1 spoken report per 20 s, and bursts are merged.
  - Report lines get a 40-token budget and 1 sentence. Every text is truncated to 80 characters.
- **Installer:** never touches the real `~/.claude/settings.json` in tests. `--apply` writes a timestamped backup first,
  merges idempotently and preserves existing hooks. `--remove` deletes only Riya's handlers.
- Games end on "stop", win or loss, or 15 turns.
- Everything green stays green, and core tests stay offline.

## Review Focus
1. **The hook receiver is hit while the core is busy speaking.** It must still answer in time, because the receiver runs
   in its own server thread.
2. **Clock jumps or sleep.** Staleness uses monotonic time where possible, and never marks an agent failed because of a
   sleep gap.
3. **The Drive log file is rewritten or truncated** (size shrinks). Reset that file's offset and don't re-report old
   lines.
4. **Many sessions at once (10+).** The snapshot stays small, and reports merge.
5. **Malicious payload text** (very long strings, control characters, prompt-injection text in
   `last_assistant_message`). It's truncated and sanitized, never interpolated into her prompt beyond an 80-character
   summary in quotes.

### Task 1: Agent hub state machine (pure)
**Files:** create `riya/agents/__init__.py`, `riya/agents/hub.py`, `tests/agents/__init__.py`, `tests/agents/test_hub.py`
- `@dataclass AgentState(id, kind, name, status, since, last_event_at, detail, needs_attention, tool_errors)`
- `@dataclass AgentEvent(kind: Literal["finished", "failed", "waiting", "lost", "stalled"], agent_id: str, name: str, text: str)`
- `class AgentHub(clock)` with:
  - `on_claude_event(payload: dict) -> list[AgentEvent]`
  - `on_colab(name: str, kind: Literal["running", "done", "fail", "lost", "stalled"], line: str) -> list[AgentEvent]`
  - `tick() -> list[AgentEvent]` for staleness and removal
  - `snapshot() -> list[dict]`, at most 20 items with newest attention first
- Sanitizing: `summarize(text, n=80)` strips control characters and collapses whitespace.
- Tests: every transition in the spec §4.2 table, staleness to unknown, removal after end, the 3-tool-failure rule,
  sanitizing, and the snapshot cap.

### Task 2: Hook receiver and runner wiring
**Files:** create `riya/agents/hooks.py`, `tests/agents/test_hooks.py`; modify `riya/core/__main__.py` (start the
receiver's uvicorn on 8766 in its own thread and feed the hub through a thread-safe queue drained by `core.tick`)
- `load_or_create_token(path) -> str`
- `create_hook_app(token: str, enqueue: Callable[[dict], None]) -> FastAPI`
- Tests: token required (401), Origin gets 403, a large body gets 413, a valid request gets 200 with an empty body and
  one enqueue, malformed JSON gets 200 with no enqueue, the token file is created once and reused, and response time
  is under 100 ms in TestClient.

### Task 3: Colab log watcher
**Files:** create `riya/agents/logwatch.py`, `tests/agents/test_logwatch.py`
- `class LogWatch(entries, kv, clock)` with `poll() -> list[tuple[name, kind, line]]`. It reads only the appended bytes
  per file, with offsets in KV under `agents.logwatch.<path>`. It resets on truncation, emits running when a file grows
  and stalled after 30 min without growth, handles a missing glob root by returning [], and never raises.
- Tests use temp files: append, done, fail, lost, truncation, stall, and a restart that keeps offsets.

### Task 4: Hooks installer
**Files:** create `riya/agents/install_hooks.py`, `tests/agents/test_install_hooks.py`
- The CLI is `python -m riya.agents.install_hooks [--print | --apply | --remove] [--settings PATH]`. The default path is
  `%USERPROFILE%/.claude/settings.json`.
- The handlers follow the spec §4.1 list (`http` type, timeout 3, header `X-Riya-Token: $RIYA_HOOK_TOKEN`,
  `allowedEnvVars`). Riya's handlers are identified by the URL `http://127.0.0.1:8766/hook`.
- `--apply` also runs `setx RIYA_HOOK_TOKEN <token>` (skipped in tests via an injectable runner) and prints restart
  instructions.
- Tests use temp settings files: create when missing, preserve other hooks and keys, idempotent double apply, remove
  restores, the backup file exists, and invalid JSON in the existing file aborts without writing.

### Task 5: Engine integration, games, protocol and settings
**Files:** modify `riya/core/engine.py`, `riya/core/prompt.py` (a `### Your agents:` line), `riya/core/settings.py`
(`agent_logs` list, validated), `riya/core/protocol.py` (`AgentsMsg {items}`; regenerate the schema), and
`riya/core/__main__.py` (build the hub and logwatch). Create `riya/core/games.py`, `tests/core/test_agents_engine.py`
and `tests/core/test_games.py`.
- The engine owns the hub. `tick` drains the hook queue into the hub, polls logwatch every 60 s, runs `hub.tick()`,
  queues events and delivers them per the Global Constraints. It emits `AgentsMsg` on change and in `hello_messages`.
- A report is generated by the local model (budget 40, 1 sentence) with a situation built from the event's sanitized
  text. Expressions by kind: failed and lost give worried, waiting gives curious, finished gives happy, stalled gives
  worried.
- Games:
  - `games.detect_start(text) -> str | None` recognizes "let's play word chain / 20 questions / riddles" or accepting an
    offer.
  - `GameState`, and `game_situation(state) -> str` with the rules and secret.
  - Bids may offer a game when at least one agent is busy.
  - The engine keeps the active game and ends it on stop, win or loss, or 15 turns.
- Tests: urgent while focused is spoken now; urgent while gaming is a bubble only; finished while focused waits for the
  break; the rate limit and merge; the prompt agents line; the game lifecycle; a game secret never in transcripts.

### Task 6: Body (agents area, badge, settings)
**Files:** modify `body/renderer.js`, `body/styles.css`, `body/index.html` (render `agents.items` into `#agents` for
panel, as a compact list for window, and as a needs-attention badge for buddy), `body/settings.html`/`settings.js`/
`src/settings-logic.js` (an Agents section: hook status as "events received in the last 24 h" from an `agents` field
`hooks_seen_at`, the token path, and editable `agent_logs`), plus fixtures and tests.
- Pure helpers: `agentChip(status)`, `relativeAge(ms)`, `badgeCount(items)`, each with tests.

### Task 7: Live agents check
**Files:** `evaluation/agents_check.py`. It reads the token, POSTs a scripted sequence (UserPromptSubmit, then
PermissionRequest, then Stop) to a running core, and prints the reports or agents messages observed over the
WebSocket. Exit 0. Not part of pytest.
