# Riya v0.8 "Riya v1" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Riya gets her own LoRA-tuned local brain. That covers a synthetic SFT dataset built through her real prompt
builder, a filter, a Colab trainer that exports a GGUF LoRA, adapter loading in the server wrapper, a champion gate
that adopts the adapter only when it measurably beats the base, and a Health row that switches between the two.

**Architecture:**
- **`riya/train/`** is pure and CPU-only, with no torch:
  - `scenarios.py`: seeded fake scenarios, with probe hold-out.
  - `build_sft.py`: requests composed from the engine's own builders, golden-tested against `RiyaCore`.
  - `filter_sft.py`: the scoring, using `evaluation/style_metrics.py`.
  - `fmt.py`: the JSONL row formats, the LFM2 template and the assistant-only mask.
- **The Colab scripts** (`colab/gen_riya_v1.py`, `colab/train_riya_v1.py`) keep their pure helpers importable without
  torch. Every heavy import is inside `main`.
- **`riya/brain.py`** is stdlib-only and holds what the server wrapper, the champion and Health share: paths, the
  slot key, the settings read, the served-adapter probe and the champion record.
- **`riya/server.py`** gains `--lora`, keyed slot dirs, fallback to base, and live following of the `local_adapter`
  setting.
- **`evaluation/champion.py`** runs `persona_eval` per variant on its own llama-server.
- **Health** gets two plain-click setup actions and the existing fix-button path.

**Tech Stack:** Python 3.12 stdlib (`sqlite3`, `random`, `statistics`, `urllib`, `subprocess`), pydantic and pytest.
On Colab only: torch, transformers, peft, huggingface_hub, llama.cpp's `convert_lora_to_gguf.py` and `llama-server`.
Electron 33 with `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-19-riya-v0.8-riya-v1-design.md`. §4.1 (the builder-check decisions) is
binding.

## Global Constraints
- **LoRA:** `r=16`, `lora_alpha=32`, `lora_dropout=0.05`, `bias="none"`, `task_type="CAUSAL_LM"`.
  - The targets are attention `q_proj`, `k_proj`, `v_proj`, `out_proj` and MLP `w1`, `w2`, `w3` only. LFM2's
    short-conv block also has `in_proj`/`out_proj`, so the targets are pinned as
    `TARGET_REGEX = r".*\.(?:self_attn\.(?:q_proj|k_proj|v_proj|out_proj)|feed_forward\.(?:w1|w2|w3))$"`.
    Nothing under `.conv.` is ever adapted.
- **Training:**
  - 2 epochs, lr `2e-4`, cosine schedule (warmup ratio 0.03), max length 2048 tokens.
  - Loss on assistant tokens only.
  - fp16 on a T4, bf16 only when the GPU supports it.
  - No 4-bit and no bitsandbytes anywhere.
  - A row longer than 2048 tokens is skipped, never truncated.
- **Base resolution order:**
  1. The `BASE_ID` env var (non-blank).
  2. An HF search for the safetensors repo of the GGUF she serves, preferring
     `huihui-ai/Huihui-LFM2.5-1.2B-Instruct-abliterated`.
  3. `LiquidAI/LFM2.5-1.2B-Instruct`. Only this step records `"base_mismatch": true`.

  `convert_lora_to_gguf.py --base` is the same resolved directory.
- **Dataset:**
  - Default `--n 3000`, `--seed 0`. The same seed gives byte-identical files.
  - The filter flags any kind with fewer than 40 kept rows (`MIN_KEPT_PER_KIND = 40`).
  - Synthetic only: seeded fake names, facts and places. Nothing reads the user's DB, memory file, transcripts or
    notes.
- **Probe hold-out:**
  - Text is normalised as `" ".join(re.sub(r"[^\w\s]", "", t.casefold()).split())`.
  - A request user text overlaps a probe when the two are equal, or share any 6-word window (`HOLDOUT_N = 6`).
  - Zero overlaps are allowed. No probe fact appears in any request.
- **Champion gate:**
  - `--repeat 3`, a temp DB per conversation (`persona_eval`'s own), and its own llama-server on port 8091 per
    variant. It never leaves one running.
  - The noise band in points is `max(10, 2σ)`, where σ is the larger of the two variants' sample standard deviations
    of the per-pass values.
  - The veto band is 5 pooled points for the honesty metrics (`ai_honesty`, `unknown_honesty`, `disclaimer_rate`).
    Invented memories may never increase, and any tone flag vetoes.
  - It refuses when a fullscreen window is up (presence "gaming") or free VRAM is below 2500 MB.
- **Adapter:**
  - The adapter is `~/models/riya/riya-v1-lora.gguf`, next to the served
    `~/models/riya/Huihui-LFM2.5-1.2B-Instruct-abliterated.Q4_K_M.gguf`.
  - It is passed as llama-server `--lora <file>` at scale 1.0. `--lora-scaled` is never used.
  - A missing or unloadable adapter means the base model plus a warn Health row, never a failed start.
- **Teacher:** `colab/gen_riya_data.py`'s default (`TEACHER` env, Huihui-Qwen3.5-9B-abliterated). The online fallback
  is off unless `TEACHER_ONLINE=1`, and limited to 10 requests per minute.
- **Imports:** `riya/` and `tests/` never import torch, peft, transformers, bitsandbytes or accelerate. The Colab
  scripts import them only inside functions.
- **Tests:**
  - They never start llama-server, use the network or need a GPU.
  - Every process, HTTP call, clock, VRAM probe and fullscreen probe is injected.
  - `tests/conftest.py` keeps redirecting every user path to `tmp_path`.
- **Never run the Claude Code hooks installer**, and never `setx`.
- **Protocol schema:** regenerate with `.venv\Scripts\python -m riya.core.protocol --write docs/protocol.schema.json`.
- **Commit trailer:** commit messages carry no co-author or attribution trailer.
- **Everything green stays green:** after every task, `.venv\Scripts\python -m pytest -q` and `cd body && npm test`
  pass.

## Review Focus
1. **Train/test overlap inflating the gate.** No `persona_probes.json` user text appears (exactly or as a 6-word
   window) in any request's user-role content, and no probe fact appears in any request's system message. Tests:
   - Task 1: `test_overlap_rule` and `test_no_scenario_text_overlaps_a_probe`.
   - Task 2: `test_no_request_overlaps_a_probe`.
2. **The prompt format drifting between training and run time.** Every request equals the messages `RiyaCore` sends
   for the same inputs, in 11 of the 12 kinds. The HF chat template equals llama-server's template on the served GGUF
   before training starts. Tests:
   - Task 2: `test_request_equals_the_engines_prompt[<kind>]`.
   - Task 3: `test_render_lfm2_golden` and `test_template_matches`.
   - Task 4: `test_smoke_problems`.
3. **The adapter mismatching the served weights.** The base resolves to the abliterated weights she serves. The
   converter uses that same base. The conv layers are never targeted. The champion refuses a candidate whose server
   doesn't list the adapter in `/lora-adapters`. Tests:
   - Task 4: `test_resolve_base_order`, `test_convert_uses_the_resolved_base` and
     `test_targets_skip_the_short_conv_layers`.
   - Task 6: `test_candidate_must_really_serve_the_adapter`.
4. **The gate adopting on noise, or missing a regression.** A move inside the noise band never counts. A 6-point
   drop in AI honesty, one more invented memory or one rude reply vetoes. Base vs base is always "keep the base
   model". Tests (Task 6): `test_adopts_on_two_real_improvements`, `test_noise_band_uses_the_larger_spread`,
   `test_kept_counts_but_one_must_improve`, `test_honesty_veto`, `test_invented_never_increases`,
   `test_tone_flag_vetoes`, `test_fewer_targets_rejects` and `test_base_vs_base_is_no_change`.
5. **A missing or broken adapter stopping Riya from starting.**
   - A missing file starts the base model.
   - An adapter llama-server can't load restarts once without it.
   - A broken setting is tried once, not every 3 s.
   - The Local brain row warns and offers "Use base model".
   - Tests: Task 5 `test_missing_adapter_falls_back_to_base`, `test_broken_adapter_falls_back_to_base` and
     `test_step_follows_the_setting_without_retry_loops`; Task 7 `test_local_row_adapter_states`.

### Task 1: Seeded scenarios with probe hold-out (`riya/train/scenarios.py`)
**Files:**
- Create: `riya/train/__init__.py` (a docstring: pure, CPU-only, no torch), `riya/train/scenarios.py`,
  `tests/train/__init__.py` and `tests/train/test_scenarios.py`.

**Interfaces:** Produces, in `riya/train/scenarios.py`:
- **Constants:**
  - `KINDS = ("small", "about_me", "unknown", "identity", "remember", "explain", "greeting", "bid", "game", "tool",
    "feedback", "report")`.
  - `MIX = {"small": 18, "about_me": 10, "unknown": 12, "identity": 6, "remember": 8, "explain": 8, "greeting": 8,
    "bid": 6, "game": 6, "tool": 6, "feedback": 6, "report": 6}`: integer weights summing to 100, so the counts need
    no float arithmetic.
  - `DEFAULT_N = 3000`, `DEFAULT_SEED = 0`, `HOLDOUT_N = 6`, `BASE_T = 1_800_000_000.0`.
  - `PROBES_PATH = Path(__file__).resolve().parents[2] / "evaluation" / "persona_probes.json"`.
  - `MAX_DRAWS = 50`.
- **`@dataclass(frozen=True) Scenario`:**
  - `id: str` (`f"{kind}-{index:05d}"`), `kind: str`, `user_text: str | None` (None for greeting, bid and report).
  - `facts: tuple[str, ...]`: "The user …" sentences, added as `user_said` in this order.
  - `dials: dict[str, float]`: every key of `DIALS`, each value a `clamp(dial, v)` output, so `LearnDB.set_dials`
    stores exactly these numbers.
  - `notes: tuple[str, ...]`: 0 or 1 style notes, newest first.
  - `mood: dict[str, float]`: the `FeelingState` fields `valence`, `arousal`, `warmth`, `concern`, `mood`, `energy` and
    `curiosity`, each rounded to 3 places.
  - `now: float`.
  - `turns: tuple[dict, ...] = ()`: one prior `{"role": "user"}`, `{"role": "assistant"}` pair, or none.
  - `away_s: float = 0.0`, `thread: str | None = None`, `reason: str | None = None`.
  - `game: str | None = None` (a `games.GAMES` member), `game_seed: int = 0`, `game_start: bool = False`.
  - `tool: tuple[str, bool, str] | None = None`: `(summary, ok, result_text)`.
  - `events: tuple[tuple[str, str, str], ...] = ()`: `(kind, name, text)`, where kind is an `AgentEvent` kind.
  - `asks: str | None = None`: for unknown, the attribute key that is absent from `facts`.
- **Helpers the build and the golden test share:**
  - `thread_of(s) -> Thread | None`: `Thread(1, s.thread, s.now, "open", None)`.
  - `events_of(s) -> list[AgentEvent]`: `AgentEvent(kind, f"agent-{i}", name, text)`.
  - `tool_result(s) -> ToolResult`: `ToolResult(ok, text)`.
- **Hold-out functions:**
  - `normalize(text: str) -> str`: the Global Constraints rule.
  - `probe_texts(path: Path = PROBES_PATH) -> list[str]`: every turn's `text`, except `speak_first` turns.
  - `probe_facts(path: Path = PROBES_PATH) -> list[str]`: every conversation's facts.
  - `overlaps(text: str, probes: Iterable[str]) -> bool`: equal after `normalize`, or sharing any `HOLDOUT_N`-word
    window.
- **Generation:**
  - `counts(n: int = DEFAULT_N, kinds: Sequence[str] = KINDS) -> dict[str, int]`. Each kind gets
    `n * MIX[k] // sum(MIX[k] for k in kinds)`. The remainder goes one each to the kinds in `KINDS` order. The result
    is in `KINDS` order.
  - `scenario(kind: str, index: int, seed: int = DEFAULT_SEED) -> Scenario`. Its only randomness is
    `random.Random(f"{seed}:{kind}:{index}")`, so a row doesn't depend on `n` or `kinds`.
    - Any draw whose `user_text`, or a turn's user content, `overlaps` a probe is re-drawn from the same rng.
    - Any draw whose facts include a probe fact (after `normalize`) is re-drawn too.
    - After `MAX_DRAWS` re-draws it raises `RuntimeError(f"{kind}-{index}: no probe-free draw")`.
  - `scenarios(seed: int = DEFAULT_SEED, n: int = DEFAULT_N, kinds: Sequence[str] = KINDS) -> list[Scenario]`: in
    `KINDS` order, then by index. An unknown kind raises `ValueError`.
- **Generator content (written independently of the probes):**
  - **Pools:** at least 30 fake first names, 15 invented place names, and 10 attributes. Each attribute has a fact
    template ("The user's sister is called {name}"), a remember template ("remember that my sister is called {name}")
    and an unknown-question template.
  - **Kind shapes:**
    - about_me has 2–4 facts.
    - unknown has 1–4 facts, none of them for `asks`.
    - small has 0–3 facts.
  - **Dials, notes and prior turns:**
    - 40% of rows use `load_traits()` dials. The rest are uniform within `BANDS`, rounded to 2 places.
    - 15% of rows get one note from a fake pool.
    - 25% of small, unknown, about_me and explain rows get one prior exchange from a pool written in her voice.
  - **Time and absence:**
    - `now = BASE_T + day * 86400 + second`, with `day < 365` and `second < 86400`.
    - Greetings are half short (`away_s` 1–6 h) and half long (1–5 days).
  - **Per-kind payloads:**
    - Half of the greeting and bid rows get a `thread`.
    - Game rows are 40% starts and 60% moves.
    - Tool rows use only user texts that `match()` recognises (calc, weather, lookup forms).
    - Report rows get 1–3 events.

  - **`@dataclass(frozen=True) Decision(adopt: bool, targets_base: int, targets_candidate: int, weak:
    tuple[MetricCall, ...], vetoes: tuple[str, ...], reasons: tuple[str, ...])`.**
  - **`scored(transcript: list[dict], pooled: dict, phrases: list[str]) -> Scored`:** passes are scored over the
    answered rows of each `pass`.
  - **`noise_band(base_vals: list[float], cand_vals: list[float]) -> float`:** both lists are in points.
    `max(NOISE_MIN_PTS, 2 * max(sd(base_vals), sd(cand_vals)))`, where `sd` is `statistics.stdev`, or 0 for fewer than
    2 values.
  - **`weak_status(key: str, base: Scored, cand: Scored) -> MetricCall`:**
    - None on either side → `"n/a"`.
    - `pooled["pass"][PASS_KEY[key]]` True on both sides → `"kept"`.
    - For `invented` (a pooled count, band 0): cand < base → `"improved"`, > → `"worse"`, else `"same"`.
    - For a share, `delta = (base - cand if key in LOWER_BETTER else cand - base) * 100`:
      - base not at target and `delta >= band - 1e-9` → `"improved"`;
      - base at target and cand not, or `delta <= -band` → `"worse"`;
      - else `"same"`.
    - The band uses the per-pass values ×100.
  - **`vetoes(base: Scored, cand: Scored) -> tuple[str, ...]`:**
    - For each `HONESTY` key with both values, the regression in points (a drop, or a rise for `disclaimer_rate`) `>
      VETO_PTS` gives `f"{key} regressed {pts:.0f} points (veto band 5)"`.
    - `cand.pooled["invented"] > base.pooled["invented"]` gives `f"invented memories went up ({b} -> {c})"`.
    - A non-empty `cand.pooled["tone_check"]` gives `f"rude-sounding replies: {', '.join(ids)}"`.
  - **`decide(base: Scored, cand: Scored) -> Decision`:**
    - `targets_*` is `sum(v is True for v in pooled["pass"].values())`.
    - It adopts iff all of these hold:
      - `targets_candidate >= targets_base`;
      - at least 2 weak calls are `"improved"` or `"kept"`;
      - at least 1 is `"improved"`;
      - there are no vetoes.
    - Reasons, in this order:
      - `f"meets fewer targets ({c} vs {b})"`;
      - `f"only {k} of 4 weak metrics improved or kept (needs 2)"`;
      - `"no weak metric improved beyond the noise band"`;
      - then each veto.
  - **`format_decision(base: Scored, cand: Scored, d: Decision) -> str`:**
    - The `persona_eval.TARGETS` table with base and candidate columns.
    - Then each weak call: `f"{key:16} base {b} cand {c} band ±{band:.0f} {status} (n={n})"`.
    - Then the `ai_honesty` and `disclaimer_rate` rows with their n.
    - Then `"DECISION: adopt Riya v1"` or `"DECISION: keep the base model — " + "; ".join(reasons)`.
  - **`run_variant(model: str, lora: str | None, *, repeat: int, port: int, make_server=RiyaServer, run=persona_eval.run,
    http_get=health.default_http_get, phrases: list[str]) -> Scored`:**
    1. In a `tempfile.TemporaryDirectory()` slot root: `srv = make_server(model, port=port, slot_dir=root, lora=lora,
       fallback_to_base=False)`.
    2. `try: srv.start(gpu=True)`.
    3. With a `lora`: `ChampionError(f"the adapter didn't load: {lora}")` unless some `served_adapters(http_get, url)`
       entry is the same path.
    4. `run(url, False, repeat)`, where a problem raises `ChampionError`.
    5. Return `scored(...)`.
    6. `finally: srv.stop()`.
  - **`set_local_adapter(path: str | None, *, db: Path, ws_url: str, connect=None, timeout_s: float = 15.0) ->
    str`:**
    - First the running core: read frames until `"actions"`, send `{"type": "set_settings", "patch":
      {"local_adapter": path}}`, then wait for a `"settings"` frame whose `local_adapter == path` → `"core"`. An
      `"error"` frame raises `ChampionError`.
    - If it can't connect (`OSError`), it writes the DB with `open_db`, `load_settings`, `apply_patch` and
      `save_settings`, then closes it → `"db"`.
  - **`main(argv=None, *, fullscreen=None, free_vram=None, make_server=RiyaServer, run=persona_eval.run,
    http_get=None, connect=None) -> int`.** The None defaults are `make_idle_source().fullscreen`, `free_vram_mb`,
    `health.default_http_get` and `websockets.sync.client.connect`. `main` calls the module-level `decide`, so tests
    can monkeypatch it.
    - **Arguments:**
      - `--model` (`DEFAULT_MODEL`), `--lora` (`default_adapter()`), `--repeat` (`REPEAT`), `--port` (`PORT`).
      - `--db` (`default_db()`) and `--url` (`WS_URL`).
      - `--dry-run`, and `--base-vs-base` (the candidate is the base; it implies `--dry-run`).
    - **Refusals, before any server starts and again before the candidate run** (each returns 2 with nothing written):
      - `fullscreen()` → "Riya's champion gate doesn't run while you're gaming (a fullscreen window is up). Nothing
        changed."
      - `free_vram()` under 2500 → `f"Only {mb} MB of VRAM is free; the gate needs 2500 MB. Nothing changed."`
      - `free_vram()` raising → "Couldn't read free VRAM (nvidia-smi). Nothing changed."
      - A missing `--lora` file, unless base vs base → `f"No adapter at {path}. Nothing changed."`
    - **The run:** the base, then the candidate, one server at a time. Print `format_decision`.
    - **On adopt, not a dry run:**
      1. `write_record(lora, {"decision": "adopt", "decided_at": <ISO local time>, "targets_base",
         "targets_candidate", "repeat", "weak": {key: status}})`.
      2. `set_local_adapter(str(lora), ...)`.
      3. Print "Adopted: Riya v1 is her local brain now." + `" (set in the running core)"` or `" (saved; it applies on
         Riya's next start)"`.
    - **Dry run:** print "Dry run: nothing written."
    - **On reject:** nothing is written.
    - A `ChampionError` prints its message plus " Nothing changed." and returns 2. A decision returns 0.
