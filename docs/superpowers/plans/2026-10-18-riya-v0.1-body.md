# Riya v0.1 Body Implementation Plan (plan 2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Riya's desktop body: an Electron app that shows her 2D sprite (blinking, breathing, talking, changing
expression and leaning) in three switchable modes, with speech bubbles, chat, a talk hotkey and a settings page, all
driven by the core over a localhost WebSocket.

**Architecture:** The body only displays and sends input. The core (plan 1) is the source of truth. All logic that can
be pure (protocol client, frame selection, blink timing, window geometry, manifest validation) lives in small CommonJS
modules under `body/src/` and is tested with `node --test`. The Electron main process manages one window, whose shape
and flags depend on the mode. The renderer is plain HTML, CSS and JS with no framework.

**Tech Stack:** Electron `33.2.1`, Node 24 (installed), `ajv@8.17.1` (dev, for the contract test) and the built-in
`node:test` runner.

**Spec:** `docs/superpowers/specs/2026-10-18-riya-v0.1-she-missed-you-design.md` (sections 5.1, 6.6 and 6.7)

**Depends on:** plan 1, Task 10 (`docs/protocol.schema.json`) for the contract, and plan 1, Task 12 (a running core on
`ws://127.0.0.1:8765/ws`) for the manual checks. Real sprites come from plan 3. Until then, the committed placeholder pack
is used.

## Global Constraints

- Connect only to `ws://127.0.0.1:8765/ws`. If it drops, reconnect with backoff (0.5 s doubling, capped at 10 s), and
  never crash.
- Exactly the 14 expressions in `docs/protocol.schema.json` (`expressions`). An unknown expression falls back to
  `neutral`.
- Expression crossfade is 150 ms. Blink every 3 to 6 s, with eyes closed for 120 ms. Breathing is a slow scale and bob on
  a period of about 4 s. Mouth frames follow `mouth` messages, which arrive at 30 Hz.
- Modes:
  - **buddy:** transparent, frameless, always on top, click-through except on her body, draggable, with its position
    remembered in `settings.buddy_position`.
  - **panel:** docked to the right edge of the work area, 320 px wide.
  - **window:** a normal 960×640 window.
- The talk hotkey is `Control+Alt+Space`. It sends `{"type": "talk_hotkey"}`.
- The sprite pack path is `settings.sprite_pack`, then `<repo>/sprites/riya-v1/`, then `body/placeholder-pack/`, in that
  order of preference. `sprites/` is gitignored. `body/placeholder-pack/` is committed (it's generated SVG, with no
  character art).
- Sprite manifest format: `body/sprite-manifest.schema.json` (Task 2). Plan 3 must produce packs that pass it.

## Review Focus

1. **The core isn't running yet, or it restarts.** The body shows her in `neutral` with a small "connecting…" hint and
   recovers on its own. Pinned in Task 1.
2. **A sprite pack is missing an expression or variant**, which happens mid-way through plan 3. The body falls back per
   frame (missing `open` uses `closed`, missing `blink` uses `closed`, a missing expression uses `neutral`) instead of
   showing a broken image. Pinned in Task 2.
3. **A saved buddy position that's now off-screen** (a monitor was unplugged, or the resolution changed). The position is
   clamped into the current work area. Pinned in Task 3.
4. **A long reply.** The bubble wraps and scrolls, so it never covers more than 40% of the screen height, and the chat
   log keeps the full text. Pinned in Task 4.
5. **Clicks pass through her transparent pixels in buddy mode**, but hovering her body makes her clickable and
   draggable. Pinned in Task 3 (the pure alpha hit test) plus a manual check.

### Task 1: Scaffold and protocol client

**Files:**
- Create: `body/package.json`, `body/src/core-client.js`, `body/test/core-client.test.js`, `body/test/fixtures/*.json`

**Interfaces:**
- Consumes: `docs/protocol.schema.json` (plan 1, Task 10).
- Produces:
  - `class CoreClient({ url, WebSocketImpl, setTimeoutFn = setTimeout })` with:
    - `connect()`
    - `on(type, fn)`, where `type` is a core message type, `"open"` or `"close"`
    - `send(obj)`, which queues messages while disconnected and flushes them on open, in order
    - `close()`
  - Reconnect delays are `0.5, 1, 2, 4, 8, 10, 10, …` seconds, and they reset after a successful open.
  - The `ws.onmessage` payload is JSON-parsed and dispatched by `type`. Bad JSON is ignored (with a log line).

- [ ] **Step 2: Write the failing tests** (`body/test/core-client.test.js`)

  - `queues sends until open then flushes in order`: `send(a)`, `send(b)`, then open. `sent` must be `[a, b]` as JSON.
  - `dispatches by type`: `on("say", fn)`, then `message({type:"say", text:"hi", ...})`. `fn` is called once with the
    object.
  - `reconnect backoff`: drop 7 times without a successful open. The recorded delays are

### Task 2: Sprite logic, the manifest contract and the placeholder pack

**Files:**
- Create: `body/src/sprite-logic.js`, `body/sprite-manifest.schema.json`, `body/tools/make-placeholder-pack.js`,
  `body/placeholder-pack/*` (generated), `body/test/sprite-logic.test.js`

**Interfaces:**
- Produces:
  - Manifest format (JSON Schema draft-07 in `sprite-manifest.schema.json`):

```json
{
  "name": "riya-v1",
  "version": 1,
  "canvas": { "width": 768, "height": 1344 },
  "crops": { "upper": [0, 0, 768, 700] },
  "expressions": {
    "neutral": { "closed": "neutral_closed.png", "open": "neutral_open.png", "blink": "neutral_blink.png" }
  }
}
```

    `name`, `version`, `canvas`, `crops.upper` and `expressions.neutral.closed` are required. The other expressions and
    variants are optional, and the fallbacks handle missing ones.
  - `validateManifest(manifest, expressions) -> string[]` returns warnings, one per missing expression or variant
    (`"missing pouty.open"`). It throws when a required field is missing.
  - `resolveFrame(manifest, expression, variant) -> string` gives the file name using the fallback chain
    `variant → closed → neutral.<variant> → neutral.closed`.
  - `class MouthGate({ openAt = 0.3, closeAt = 0.15 })` with `update(level) -> boolean` (open or not, with hysteresis).
  - `class BlinkScheduler({ rng = Math.random, minMs = 3000, maxMs = 6000, closedMs = 120 })` with
    `isClosed(nowMs) -> boolean`. It's deterministic for a given rng.
  - `breathing(tMs) -> { scale, dy }` has a period of 4000 ms, scale in `[1.0, 1.012]` and dy in `[0, -3]` px.
  - `leanFor({ presence, curiosity }) -> { rotateDeg, dx }` returns `{-6, -12}` when presence is `focused` and
    curiosity > 0.6, and `{0, 0}` otherwise. (In phase 2 the direction will follow the active window.)
  - `frameFor({ manifest, expression, mouthOpen, blinking }) -> string` prefers blink while blinking, otherwise open
    when the mouth is open, otherwise closed. It goes through `resolveFrame`.
  - `make-placeholder-pack.js` writes 14 × 3 SVG frames plus `manifest.json` into `body/placeholder-pack/`. Each frame
    is a simple chibi with a per-expression eye and mouth shape and a label, on a 384×672 canvas.

- [ ] **Step 1: Write the failing tests** (`body/test/sprite-logic.test.js`)
  - `placeholder pack validates with no warnings`: `validateManifest(require('../placeholder-pack/manifest.json'), EXPRESSIONS)`
    returns `[]`. `EXPRESSIONS` is read from `docs/protocol.schema.json`.
  - `missing variants fall back`: given a manifest with only `neutral.closed` and `happy.closed`,
    - `resolveFrame(m, "happy", "open")` returns `"happy_closed.png"`,
    - `resolveFrame(m, "sad", "blink")` returns `"neutral_closed.png"`,
    - and `validateManifest` contains `"missing happy.open"`.
  - `manifest without neutral.closed throws`.
  - `mouth gate hysteresis`: `[0.2, 0.31, 0.2, 0.14, 0.2]` gives `[false, true, true, false, false]`.
  - `blink timing`: with a seeded rng (an LCG with seed 1), the gaps between blink starts across 50 blinks are all in
    `[3000, 6000]`, and each closed span lasts 120 ms.
  - `breathing bounds`: over `t = 0..8000` in steps of 50, scale stays in `[1, 1.012]` and dy stays in `[-3, 0]`.
  - `frameFor prefers blink then open`.

  Run `npm --prefix body test`. Expected: FAIL.

### Task 3: Windows for the three modes, click-through and dragging

**Files:**
- Create: `body/src/geometry.js`, `body/src/hit-test.js`, `body/main.js`, `body/preload.js`,
  `body/test/geometry.test.js`

**Interfaces:**
- Consumes: `CoreClient` (the main process owns the single connection and relays to the renderer over IPC), and
  `settings` (from `SettingsMsg`).
- Produces:
  - `boundsFor(mode, workArea, savedPos, size = { buddy: [300, 520] }) -> { x, y, width, height }`:
    - buddy: `savedPos` clamped into the work area, or the bottom-right corner with a 24 px margin.
    - panel: `x = wa.x + wa.width - 320`, `y = wa.y`, `width = 320`, `height = wa.height`.
    - window: 960×640, centered.
  - `clampToArea(rect, workArea) -> rect`.
  - `isOpaqueAt(alpha: Uint8ClampedArray, width, x, y, threshold = 16) -> boolean`, where `alpha` holds RGBA data.
  - The main process creates the window for the mode:
    - **buddy:** `transparent: true`, `frame: false`, `alwaysOnTop: true`, `skipTaskbar: true`,
      `resizable: false`, and `setIgnoreMouseEvents(true, { forward: true })`.
    - **panel:** frameless and always on top.
    - **window:** framed, normal.
  - When `SettingsMsg.settings.mode` changes, the main process recreates the window.
  - IPC: `click-through(bool)` comes from the renderer's hover hit test.
    `drag-start` makes the main process poll `screen.getCursorScreenPoint()` at 60 Hz until `drag-end`, then send
    `set_settings { buddy_position: [x, y] }`.
  - The tray menu has Buddy / Panel / Window (each sends `set_settings { mode }`), Settings… and Quit. On Windows the tray
    uses a 16 px PNG (generated or a simple circle).
  - `globalShortcut.register("Control+Alt+Space", …)` sends `talk_hotkey`.
  - The core client is relayed to the renderer, both ways, over the `core:message` and `core:send` channels.

  - `buddy saved position off-screen is clamped`: a saved position of `[5000, -300]` gives `{x:1620, y:0, ...}`.
  - `panel docks right`: `{x:1600, y:0, width:320, height:1040}`.

  - `alpha hit test`: in a 2×1 RGBA buffer with alpha `[0, 255]`, `isOpaqueAt(...,0,0)` is false and

### Task 4: The stage: sprite animation, bubbles and chat

**Files:**
- Create: `body/index.html`, `body/styles.css`, `body/renderer.js`, `body/src/bubble.js`, `body/test/bubble.test.js`

**Interfaces:**
- Consumes: `CoreClient` messages over IPC, and the sprite logic (Task 2).
- Produces:
  - Sprite stack: two `<img>` layers crossfade with `transition: opacity 150ms`. A `requestAnimationFrame` loop applies
    `breathing`, `leanFor` and blinking. `mouth` messages drive the `MouthGate`, and `expression` and `state` messages set
    the current expression.
  - For the panel mode, the upper crop comes from `manifest.crops.upper` (CSS `object-view-box` or a positioned `<img>`
    inside a clipping box).
  - `class BubbleModel` is a pure module:
    - `onSay({ utterance_id, text, kind })` appends to the current utterance.
    - `onSayEnd(id, nowMs)` starts a 6000 ms hide timer.
    - `visible(nowMs) -> boolean`, `text() -> string` and `kind() -> string`.
    - A new utterance replaces the old one.
    - `bid` bubbles stay until the next user input or 60 s.
  - The bubble's CSS has `max-height: 40vh; overflow-y: auto`. Chat log entries are added for user texts and complete
    utterances. The text input sends `user_text` on Enter and ignores empty input. The buddy mode has no chat log, only
    bubbles. Panel and window show the log and the input.
  - While disconnected, a "connecting…" hint shows and she's displayed in `neutral`.

### Task 5: Settings page, memory list and launcher

**Files:**
- Create: `body/settings.html`, `body/settings.js`
- Modify: `body/main.js` (open settings from the tray), `scripts/start_riya.ps1`

**Interfaces:**
- Consumes: `SettingsMsg`, `MemoriesMsg`, `ErrorMsg`; and it sends `set_settings`, `get_memories`, `memory_delete`,
  `memory_correct` and `transcript_delete`.
- Produces:
  - A settings window (a normal framed window, 520×720) with these controls, each sending one `set_settings` patch:
    mode, voice (with a note that it applies after a restart), volume, mute her voice, mute mic, start with Windows,
    online model on/off, use online for memory summaries (with the explanation "Google may use free-tier data"), "she may
    start conversations", and quiet hours (`HH:MM-HH:MM`).
  - The API key isn't editable here. The page says to put `RIYA_ONLINE_API_KEY` in `.env`, so the key is never sent
    over the socket or shown in the UI.
  - Memory list: each fact shows its text, its source as a badge (user said / inferred / looked up / conflicting) and
    when it was learned, with **Correct** (an inline edit that sends `memory_correct`) and **Delete** (a confirm dialog
    with the checkbox "also delete conversations that mention this", which sends `memory_delete` with
    `delete_episodes`).
  - Transcripts: a list of days, each with a delete button.
  - An `ErrorMsg` appears inline next to the control that caused it.
  - `start_riya.ps1`: after the core's port 8765 accepts connections, it runs `npm --prefix body start`.
