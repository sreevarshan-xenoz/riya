# Riya v0.1 Core Implementation Plan (plan 1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Riya core: one Python process that owns her memory, feelings, persona, model routing, presence, initiative and voice, and talks to the body over a localhost WebSocket.

**Architecture:** This is a new package, `riya/core/`, made of small, single-purpose modules. Each takes an injected `clock`, `db`, models and an idle source, so every behaviour is testable with fakes and with no GPU, network or microphone. `RiyaCore` (engine) wires the modules together. `app.py` exposes it over FastAPI WebSockets. `__main__.py` runs it alongside the existing voice loop and the existing llama-server game-mode wrapper.

**Tech Stack:** Python 3.12, SQLite (stdlib `sqlite3`, WAL), numpy, pydantic v2, FastAPI with uvicorn, fastembed (`BAAI/bge-small-en-v1.5`, lazy-loaded), and the existing Pocket TTS, Moonshine, Silero and sounddevice. Tests use pytest and FastAPI's `TestClient`.

**Spec:** `docs/superpowers/specs/2026-10-18-riya-v0.1-she-missed-you-design.md`

**Sibling plans:** `2026-10-18-riya-v0.1-body.md` (the Electron body, which consumes this plan's protocol) and
`2026-10-18-riya-v0.1-sprites.md` (the Colab sprite pack). This plan comes first. The sprite plan can run in parallel.

## Global Constraints

- Windows 11 laptop, Python 3.12. No Docker, no Postgres, no cloud server. Zero recurring cost.
- The core listens only on `127.0.0.1`.
- Never commit any of these: `riya images/`, `sprites/`, `*.db`, `.env`, `.superpowers/`.
- `jarvis/` isn't modified. Everything under `tests/` that passes today must still pass.
- Core tests run without torch, GPU, network or a microphone: `python -m pytest tests/core -q`. Heavy imports (fastembed,
  pocket_tts, moonshine_voice, sounddevice, torch) happen lazily inside the classes that need them.
- Online model: the OpenAI-compatible Gemini free tier. Defaults are `RIYA_ONLINE_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai`
  and `RIYA_ONLINE_MODEL=gemini-2.5-flash`, and the key is in `RIYA_ONLINE_API_KEY` in a gitignored `.env`. If no reply
  starts within 8 s, use the local model.
- A hard-thinking turn sends only the persona, her feeling state, recent turns and the memories retrieved for that turn.
  Consolidation uses the local model unless `settings.online_consolidation` is true.
- Local model for v0.1: `~/models/riya/Huihui-LFM2.5-1.2B-Instruct-abliterated.Q4_K_M.gguf`, served by the
  existing `riya/server.py` on port 8090.
- Spec constants, copied verbatim:
  - Away after 15 min idle or when the session is locked. A break is a 2 to 15 min gap, plus 60 s after input resumes.
  - The coming-home greeting needs at least 2 h away.
  - Bids for attention: at least 90 min apart, only on a break, and only after more than 2 h of work or with a due
    thread. A thread is raised at most once per day.
  - The listen window stays open about 2 min after the last turn.
  - Consolidation runs after 10 min of quiet.
  - Transcripts are kept 30 days.
  - Missing-you is about 0.1 at 2 h, 0.5 at 1 day and 0.85 at 2 days, with clinginess 0.8 as the reference, and decays
    within 10 to 20 min of being together.
  - Mouth levels are sent at 30 Hz.
- Honesty: she never states a memory she wasn't given. When nothing relevant is retrieved, the prompt says she doesn't
  remember.

## Review Focus

1. **The laptop sleeps, or the clock jumps backwards.** A gap longer than 15 min between two presence updates counts as
   away from the last update, and `away_s` is never negative. Pinned in Task 8.
2. **The online model drops mid-reply after it has started speaking.** Keep what was already said, raise nothing, and
   finish the turn. Pinned in Task 6.
3. **Typed and spoken input arrive at the same time.** Replies are serialized, so transcript turns never interleave.
   Pinned in Task 11.
4. **The body sends malformed JSON or an unknown message type.** The core answers with `error` and the socket stays
   open. Pinned in Task 12.
5. **Emoji and non-English text** (the user's own folder is called `cute alya 💞`) round-trips unchanged through SQLite,
   embeddings and prompts. Pinned in Task 2.

### Task 2: Embeddings and facts (provenance, duplicates, supersession, forgetting)

**Files:**
- Create: `riya/core/embed.py`, `riya/core/memory.py`, `tests/core/test_memory_facts.py`

**Interfaces:**
- Consumes: `open_db`, `FakeClock` (Task 1).
- Produces:
  - `Embedder` protocol: `dim: int` and `embed(texts: list[str]) -> np.ndarray`. It returns `(n, dim)` float32 rows
    that are L2-normalized. An all-zero row is allowed for text that has no tokens.
  - `HashEmbedder(dim: int = 512)` is deterministic and has no dependencies. It tokenizes with `[a-z0-9]+` on
    lowercased text, drops `STOPWORDS`, and hashes unigrams and bigrams with `zlib.crc32` into buckets.
  - `FastEmbedder(model: str = "BAAI/bge-small-en-v1.5")` imports fastembed lazily.
  - `STOPWORDS` is a frozenset that includes common English function words plus `user`, `s`, `riya` and `you`.
  - `@dataclass Fact(id: int, text: str, key: str | None, source: str, confidence: float, valid_from: float, valid_until: float | None, status: str, supersedes_id: int | None)`.
  - `Memory(db, embedder, clock, dup_sim: float = 0.92, forgotten_sim: float = 0.85, min_sim: float = 0.2)` with:
    - `add_fact(text, source, confidence=0.9, key=None, episode_id=None) -> Fact | None`
    - `correct(fact_id, new_text) -> Fact`
    - `delete_fact(fact_id, delete_episodes=False) -> None`
    - `list_facts(include_superseded=False) -> list[Fact]`, ordered by id
    - `history(fact_id) -> list[Fact]`, newest first, following `supersedes_id`
  - `Memory.db` is a public attribute.

  `add_fact` rules, in order:
  1. Return `None` if the text matches a `forgotten` row, either by the same non-null key or by cosine ≥ `forgotten_sim`.
  2. Return `None` if the text duplicates an active or conflict fact (cosine ≥ `dup_sim`).
  3. If an active fact has the same `key` and different text:
     - If the new source is `user_said` and the old one isn't, the old fact becomes `superseded` (with `valid_until=now`)
       and the new fact gets `supersedes_id=old.id`.
     - If both sources have the same rank, both facts become `conflict`.
     - If the old source outranks the new one, the new fact is stored as `conflict` and the old one becomes `conflict` too.

  Rank order: `user_said` > `looked_up` > `inferred`.

  `correct` creates a `user_said` fact that supersedes the old one. `delete_fact` hard-deletes the row and inserts
  `forgotten(description=fact.key or fact.text[:60], key=fact.key, embedding=<embedding of fact.text>)`.

### Task 3: Episodes, open threads, transcripts, retrieval, legacy import

**Files:**
- Modify: `riya/core/memory.py`
- Create: `tests/core/test_memory_recall.py`

**Interfaces:**
- Consumes: `Memory`, `Fact` (Task 2).
- Produces:
  - `@dataclass Episode(id: int, started_at: float, ended_at: float, summary: str, user_mood: str | None, outcome: str | None)`.
  - `@dataclass Thread(id: int, text: str, due_at: float, status: str, last_raised_at: float | None)`.
  - `@dataclass Retrieved(facts: list[Fact], episodes: list[Episode], threads: list[Thread])`.
  - New `Memory` methods:
    - `add_episode(started_at, ended_at, summary, user_mood=None, outcome=None) -> Episode`
    - `recent_episodes(n=3) -> list[Episode]`, newest `ended_at` first
    - `add_thread(text, due_at, episode_id=None) -> Thread`
    - `due_threads() -> list[Thread]`: open threads with `due_at <= now`, latest `due_at` first
    - `mark_thread(thread_id, status=None, raised_at=None) -> None`: a `None` argument leaves that field unchanged
    - `append_transcript(role, text) -> int`
    - `unconsolidated() -> list[dict]` with keys `id`, `at`, `role` and `text`
    - `mark_consolidated(ids) -> None`
    - `purge_transcripts(max_age_s=30 * 86400) -> int`
    - `transcript_days() -> list[str]` (`YYYY-MM-DD`, local time)
    - `delete_transcript_day(day: str) -> int`
    - `retrieve(query, k_facts=5, k_episodes=2) -> Retrieved`
    - `import_legacy_json(path) -> Episode | None`
  - Retrieval score: `0.6 * sim + 0.25 * exp(-age_days / 30) + 0.15 * quality`. Quality is 1.0 for `user_said`, 0.7 for
    `looked_up` and 0.5 for `inferred`.
    - Facts: only `active` or `conflict` facts with `sim >= min_sim` are eligible.
    - Episodes: an episode is included when its `sim >= min_sim`.
    - Threads: `due_threads()`.
  - `import_legacy_json` reads `{"summary": ...}` and stores it as one episode with `started_at = ended_at = now` and
    `outcome="imported"`. It returns `None` if the file is missing or the summary is empty.
  - `delete_fact(..., delete_episodes=True)` also deletes episodes whose embedding similarity to the fact is ≥ 0.6, plus
    the fact's `episode_id`.

### Task 4: Feelings (momentary affect, mood, missing you, user-mood estimate, expression)

**Interfaces:**
- Consumes: `FakeClock`.
- Produces:
  - `appraise(text, prev_words) -> (valence, arousal, novelty)`, moved unchanged. `SENTENCE_END` is moved too.
  - `missing_curve(hours: float) -> float`. It interpolates linearly through `(0,0), (2,0.10), (24,0.50), (48,0.85)`.
    Past 48 h it's `0.85 + 0.15 * (1 - exp(-(h - 48) / 48))`.
  - `@dataclass UserMood(valence: float = 0.0, confidence: float = 0.0, label: str = "unknown")`.
  - `@dataclass FeelingState(valence=0.1, arousal=0.3, warmth=0.6, concern=0.0, playfulness=0.4, surprise=0.0, mood=0.1, missing=0.0, energy=0.8, curiosity=0.5, user_mood=UserMood())`.
  - Constants:
    - `AFFECT_HALF_LIFE_S = 300` (valence, arousal, concern and surprise decay toward mood or baseline)
    - `MOOD_TAU_S = 6 * 3600`
    - `MISSING_HALF_LIFE_S = 240` (only while present)
    - `MAX_TURN_DELTA = 0.35`
  - `Feelings(clock, traits: dict[str, float])` with:
    - `state: FeelingState`
    - `on_return(away_s)`: sets `missing = min(1, missing_curve(h) * clinginess / 0.8)`, adds a burst of

      expression override of `missed_you` if missing ≥ 0.4, otherwise `happy`.
    - `on_user_text(text)`: calls `estimate_user`, then moves her own affect toward the appraisal, with empathy toward
      negative user mood raising `concern`. Each of valence and arousal changes by at most `MAX_TURN_DELTA` per call.
    - `estimate_user(text)`: updates only `state.user_mood`. Confidence is `min(0.8, 0.3 + 0.1 * <number of affect words>)`.
    - `on_event(name)`: `"bid_ignored"` gives a 30 s `pouty` override, `"thinking"` and `"thinking_done"` toggle a
      `thinking` override, and `"teased"` gives a 10 s `teasing` override.
    - `tick(present: bool)`: decays using the time since the last tick. The first tick after `from_dict` uses the time

  - It buffers text until the first `SENTENCE_END` match or 160 characters, then checks `REFUSAL_PATTERNS`. On a refusal

    and nothing is raised.

  `\b(debug|traceback|error|exception|explain|how (do|does|can|to)|why (is|does|do)|write (a|me|the)|code|function|script|plan|compare|calculate|translate|summari[sz]e)\b`;

```python
import re

from riya.core.models import ModelUnavailable


class FakeModel:
    def __init__(self, name="fake", replies=("Okay.",), fail=None, fail_after=None):
        self.name, self.replies, self.fail, self.fail_after = name, list(replies), fail, fail_after
        self.calls = []

    def stream(self, messages, max_tokens=300, temperature=0.8):
        self.calls.append(messages)
        if self.fail:
            raise self.fail
        text = self.replies[min(len(self.calls) - 1, len(self.replies) - 1)]
        for i, tok in enumerate(re.findall(r"\S+\s*", text)):
            if self.fail_after is not None and i == self.fail_after:
                raise ModelUnavailable("dropped mid-stream")
            yield tok
```

**Interfaces:**

- Produces:
  - `RiyaCore(*, db, embedder, clock, idle_source, local, online, emit: Callable[[BaseModel], None], persona: str | None = None)`.
    It builds `KV`, `Memory`, `Feelings` (restored from KV key `feelings`), `Presence`, `Settings`, `Initiative`,
    `Router` and `Consolidator` itself. The consolidation model is `online` only if
    `settings.online_consolidation and online`, otherwise `local`.
  - Public attributes: `memory`, `feelings`, `presence`, `kv`, `settings` (a property reading KV), `turns`.
  - `reply(text: str, source: Literal["typed", "voice"] = "typed") -> Iterator[str]` yields sentences. Under one
    `threading.Lock` held for the whole reply, it does the following:
    1. Appends the user transcript and handles `remember_intent`, saving a `user_said` fact with the text
       `"The user said: {x}"`.
    2. Calls `feelings.on_user_text` and `presence.note_turn`.
    3. Retrieves memories, builds the messages and streams them through `Router`.
    4. When the route is online, emits `ExpressionMsg("thinking")` first and `thinking_done` at the first sentence.
    5. Splits the output with `SENTENCE_END` and emits a `Say(kind="reply", spoken=not settings.mute_voice)` for each
       sentence.
    6. Emits `SayEnd` and appends the assistant transcript.
    7. Keeps the last 24 messages in `turns`, clears any pending bid, and emits `ExpressionMsg` whenever `expression()`
       changes.
  - `tick() -> Iterator[str] | None`, called about once a second by the runner, does the following:
    1. Calls `presence.update()`.
    2. On `came_back`: calls `feelings.on_return(away_s)`. If `initiative.on_came_back` returns a greeting, it marks the
       thread `followed_up`, sets `raised_at`, and returns `speak_first(action)`.
    3. On `break_started` (or while on a break): calls `initiative.on_break(...)`. A bid emits one
       `Say(kind="bid", spoken=False)` line from the local model (`max_tokens=40`) and records `pending_bid_at`.
    4. If a pending bid gets no user turn within 300 s, calls `feelings.on_event("bid_ignored")` and clears the bid.
    5. Calls `feelings.tick(present=presence.state != "away")`. If `consolidator.due(last_turn_at)`, runs consolidation
       inline (it's quick, and it's the local model).
    6. Calls `memory.purge_transcripts()` once a day.
    7. Every 30 s, persists the feelings to KV and emits a `StateMsg`.
    8. Returns `None` when there's nothing to speak.
  - `speak_first(action) -> Iterator[str]` is like `reply`, but uses `user_text=None` and
    `greeting_situation(...)`, and emits `Say(kind="greet", spoken=True)`.
  - `handle(msg: BodyMessage) -> None` handles every message except `UserText`:
    - `GetMemories` emits a `MemoriesMsg` with `facts=[asdict(f) for f in list_facts()]` and
      `transcript_days=memory.transcript_days()`.
    - `MemoryDelete`, `MemoryCorrect` and `TranscriptDelete` apply the change, then emit a fresh `MemoriesMsg`.
    - `SetSettings` calls `apply_patch` then `save_settings`, calls `set_autostart` when `autostart` changes, and emits
      a `SettingsMsg`. A `ValueError` emits `ErrorMsg`.
    - `TalkHotkey` sets `self.talk_requested = True`, which the voice loop reads.
  - `voice_state() -> tuple[SimpleNamespace, float]` returns `(SimpleNamespace(arousal=..., valence=...), energy)`, which

### Task 12: WebSocket app, runner and launcher

**Files:**
- Create: `riya/core/app.py`, `riya/core/__main__.py`, `scripts/start_riya.ps1`, `tests/core/test_app.py`

**Interfaces:**
- Consumes: `RiyaCore`, `protocol`.
- Produces:
  - `Hub` has `attach(loop)` and `publish(msg: BaseModel)`. `publish` is thread-safe: it uses `loop.call_soon_threadsafe`
    to put the message on each connection's `asyncio.Queue`.
  - `create_app(core_factory: Callable[[Callable[[BaseModel], None]], RiyaCore]) -> FastAPI`:
    - It builds the core with `emit=hub.publish` at startup.
    - The `/ws` endpoint sends `core.hello_messages()` and then forwards the hub queue.
    - `UserText` is consumed with `await run_in_threadpool(lambda: list(core.reply(text)))`. The `Say`/`SayEnd` events
      reach the client through the hub. In the runner, voice speaks them instead (see Task 13).
    - Any other message goes to `core.handle`.
    - A `ProtocolError` sends an `ErrorMsg` and keeps the socket open.
    - The app is exposed as `app.state.core`.
  - `DEFAULT_HOST = "127.0.0.1"` and `DEFAULT_PORT = 8765`.
  - `build_core(args, emit) -> RiyaCore` uses `OpenAICompatModel("local", f"{args.local_url}/v1")`,
    `load_online_from_env()` after `load_dotenv()`, `FastEmbedder()` (or `HashEmbedder()` with `--hash-embed`), and
    `make_idle_source()`. On first run (KV flag `legacy_imported`) it imports `riya_memory.json`.
  - `main()` takes these arguments: `--db` (default `%LOCALAPPDATA%/Riya/riya.db`),
    `--local-url http://127.0.0.1:8090`, `--port 8765`, `--no-voice`, `--hash-embed` and
    `--legacy-memory riya_memory.json`. It runs uvicorn in a thread and a 1 s `tick()` loop on the main thread. Each
    iterator that `tick()` returns is spoken (Task 13) or, with `--no-voice`, drained.
  - `scripts/start_riya.ps1` takes the parameter `-Model` (default is the GGUF path in Global Constraints). It starts
    `python -m riya.server --model $Model` minimised, waits for `http://127.0.0.1:8090/health`, then runs
    `python -m riya.core`. Plan 2 extends it to start the body.

### Task 13: Voice: listen gate, barge-in margin, mouth levels, candidate voices

**Files:**
- Create: `riya/core/listen.py`, `riya/voice_candidates.py`, `tests/core/test_listen.py`
- Modify: `riya/voice.py`, `riya/core/__main__.py`

**Interfaces:**
- Consumes: `RiyaCore.reply`, `voice_state`, `talk_requested`, `presence.state`, `Mouth`; and `PocketTTS`,
  `SileroVAD`, `MoonshineStreamSTT` from `riya/voice.py`.
- Produces:
  - `WAKE_WORDS = ("riya", "ria", "reya", "riyaa")`.
  - `ListenGate(clock, open_window_s=120)` with:
    - `open(reason: str)`
    - `is_open() -> bool`
    - `note_turn()`, which restarts the window
    - `accept(transcript: str, gaming: bool) -> str | None`:
      - If the gate is open, it returns the transcript.
      - If the gate is closed, gaming is false and a wake word appears as a whole word: it opens the gate and returns
        the transcript.
      - Otherwise it returns `None`.
  - `barge_in_ok(mic_rms: float, playback_rms: float, ratio: float = 2.5, floor: float = 0.02) -> bool` returns
    `mic_rms > max(ratio * playback_rms, floor)`.
  - `mouth_levels(chunk: np.ndarray, sr: int, fps: int = 30) -> list[float]` gives the RMS per `sr // fps` window,
    computed as `min(1, rms / 0.15)`, one value per window.
  - `riya/voice.py` changes:
    - `VoiceLoop(core, stt, tts, vad, gate, on_mouth: Callable[[float], None])`.
    - `listen()` applies barge-in only when `barge_in_ok(rms(chunk), self.playback_rms)` is true, where
      `playback_rms` is updated in `say()`.
    - `run()` transcribes each utterance, passes it through `gate.accept(text, gaming=core.presence.state == "gaming")`,
      and when it's accepted calls `say(core.reply(text, source="voice"))` and then `gate.note_turn()`.
    - `core.talk_requested` opens the gate (and resets the flag). When gaming, only the hotkey opens it.
    - `say(sentences)` takes its parameters from `voice_params(*core.voice_state())`. It reports each written chunk
      through `on_mouth` (at 30 Hz, with the chunks spaced by sleeping per frame), sends `on_mouth(0.0)` at the end,
      and respects `settings.mute_voice` (it skips playback but still drains the sentences) and `settings.volume`.
    - `voice_params` is unchanged.
  - `__main__` with voice:
    - Builds `PocketTTS(settings.voice)`, `MoonshineStreamSTT("small")` and `SileroVAD()`.
    - Wires `on_mouth=lambda l: hub.publish(Mouth(level=l))`.
    - Speaks `tick()` iterators through `loop.say`, then `gate.open("spoke_first")`.
    - When `mute_mic` is set, the mic stream is paused.
  - `riya/voice_candidates.py` takes `--out scratch_runs/voice_candidates`, `--voices` (default: the built-in voice
    names the installed `pocket_tts` package exposes, filtered by the implementer to the feminine-sounding ones, or
    `alba` if the package exposes no list) and `--text "You're back! I missed you~ How was your day?"`. It writes one
    WAV per voice so the user can choose one. The chosen name goes into `settings.voice`.
