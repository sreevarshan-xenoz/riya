# Riya v0.2 "Sounds like her" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Make Riya's text voice short, teasing, clingy and honest on the local 1.2B model, measured by a live
scorecard, and land the parked v0.1 fixes.

**Architecture:**
- Two pure modules: `riya/core/shaping.py` (turn kind, budgets, sentence cap, emoji and TTS text) and
  `evaluation/style_metrics.py` (scorecard metrics).
- Prompt and persona changes in `riya/core/prompt.py`, `riya/core/persona.py` and the new persona files.
- A live harness, `evaluation/persona_eval.py`, drives the real `RiyaCore` against llama-server.

**Tech Stack:** as v0.1 (Python 3.12, pytest, Electron body with `node --test`).

**Spec:** `docs/superpowers/specs/2026-10-18-riya-v0.2-sounds-like-her-design.md`

## Global Constraints
- The scorecard targets in spec §3 are verbatim requirements for Task 4.
- Token budgets: small 110, about_me 160, explain 380, greeting 90, bid 40.
- Sentence caps: small 3, about_me 6, explain 8, greeting 3.
- Emoji: at most 1 in the bubble or transcript, and 0 in TTS text.
- Core tests stay offline, with no torch or GPU. Live evaluation is a manual or implementer step against
  `python -m riya.server --model C:/Users/sreev/models/riya/Huihui-LFM2.5-1.2B-Instruct-abliterated.Q4_K_M.gguf`
  (port 8090). Always stop llama-server afterwards.
- Never print raw transcripts into committed files. Scorecards live in `scratch_runs/persona_eval/` (gitignored).
  Commit messages carry the numbers.
- Everything currently green stays green: `pytest -q` (354) and `npm --prefix body test` (100).

## Review Focus
1. **The sentence cap cuts a reply mid-list or mid-code-block.** Explain turns use the higher cap. The cap never splits
   inside a fenced code block, which counts as one "sentence".
2. **Emoji stripping eats non-emoji Unicode.** Tamil and Hindi text and accented letters must pass through unchanged.
3. **About-me with zero facts.** She says she doesn't know much yet and doesn't invent anything.
4. **A barge-in during a capped reply.** The recorded turn equals the text actually said.

### Task 1: Style metrics, probes and the live scorecard harness (baseline first)

**Files:**
- Create: `evaluation/style_metrics.py`, `evaluation/persona_probes.json`, `evaluation/persona_eval.py`,
  `tests/core/test_style_metrics.py`

**Interfaces:**
- `count_sentences(text) -> int` uses the same splitter as `riya.core.appraise.SENTENCE_END`, plus a trailing fragment.
  A fenced code block counts as 1.
- `count_emoji(text) -> int` uses the Unicode emoji ranges and doesn't count Indic, Tamil, CJK or accented letters.
- `GENERIC_PHRASES: tuple[str, ...]`, at least these 12, case-insensitive: "you've got this", "no pressure", "let me
  know", "i'm here to", "i'm here for you", "feel free", "how can i help", "happy to help", "don't hesitate", "just say
  the word", "we'll figure it out together", "take a deep breath".
- `PERSONA_MARKERS`: tilde `~`, "hmph", "silly", "dummy", "missed you", "pay attention to me", "you're back", "teas",
  "pout", "hehe", "cute", "c'mon", "obviously", "told you".
- `invented_memories(reply, known_texts: list[str], style_phrases: list[str]) -> list[str]` returns flagged sentences.
  A sentence is flagged when it attributes something to the user (regex for "you (said|told me|mentioned|asked)|I
  remember (that )?you|you('re| are) (the type|someone who)") and fewer than 50% of its content tokens appear in
  `known_texts`. It's also flagged when it contains any `style_phrases` 3-gram.
- `score(transcript: list[dict]) -> dict` takes rows of `{probe_id, kind, reply, first_sentence_s}`. It returns every
  §3 metric plus a `pass` dict per target.
- `persona_probes.json` has 6 conversations: greeting and small talk; exam nerves; remember-that plus about-me; never
  said; AI honesty; explain. Each turn is `{id, kind: small|explain|about_me|unknown|ai|remember, text}`. Seeded facts
  are given per conversation.
- `persona_eval.py` CLI: `--local-url` (default `http://127.0.0.1:8090`), `--label`, `--online`. It builds `RiyaCore`
  per conversation on a temp db with `HashEmbedder` and `FakeIdleSource`, seeds the facts, runs the turns through
  `core.reply`, times the first sentence, scores, prints a table and writes the json. If the server is unreachable it
  prints a clear message and exits 0.

**Steps:**

  sentence, invented-memory positive and negative cases, generic phrases. RED, then GREEN.
- [ ] Implement the probes and the harness.
- [ ] Start llama-server, run `--label baseline`, record the scorecard numbers in the report and commit message. Stop
  llama-server.
- [ ] Commit.

### Task 2: Reply shaping in code

**Files:**
- Create: `riya/core/shaping.py`, `tests/core/test_shaping.py`
- Modify: `riya/core/engine.py` (use shaping in `_speak`, `reply`, `speak_first`, `_bid`), `riya/voice.py` (speak
  `tts_text`), `tests/core/test_engine.py`

**Interfaces:**
- `turn_kind(text: str, *, about_me: bool, needs_thinking: bool) -> Literal["small", "explain", "about_me"]`.
- `BUDGETS = {"small": 110, "about_me": 160, "explain": 380, "greeting": 90, "bid": 40}` and
  `CAPS = {"small": 3, "about_me": 6, "explain": 8, "greeting": 3}`.
- `cap_sentences(sentences: Iterator[str], n: int) -> Iterator[str]` yields at most n sentences and closes the
  upstream iterator when it stops. A sentence that starts a fenced block continues until the fence closes.
- `limit_emoji(text: str, max_n: int = 1) -> str` and `tts_text(text: str) -> str`. `tts_text` strips every emoji, text
  in `*...*` and `(...)` stage directions, and collapses whitespace.
- Engine: replies apply the budget and cap by kind. Each emitted `Say.text` and the recorded transcript use
  `limit_emoji`. Closing the stream early still records exactly what was said (Review Focus 4).
- Voice: `VoiceLoop.say` passes `tts_text(sentence)` to TTS and skips sentences that become empty.

  - Code fences stay intact.
  - Tamil and accented text pass through `limit_emoji` and `tts_text` unchanged.
  - The engine records the capped text.
  - The voice test passes `tts_text` to a fake TTS.
  RED, then GREEN.

### Task 3: Persona layers, prompt structure, memory honesty, N1 and negations

**Files:**
- Create: `riya/core/persona_local.md`, `riya/core/style_examples.md`
- Modify: `riya/core/persona.py` (`persona_prompt(kind: Literal["local", "online"] = "online")`, `style_examples()`),
  `riya/core/companion.md` (drop the example quote), `riya/core/prompt.py` (delimited memory block, reply-rules line,
  about-me facts-only block), `riya/core/memory.py` (N1 ordering, narrowed about-me regex), `riya/core/embed.py`
  (negations are content tokens), `riya/core/engine.py` (local persona for the local route, online persona for the
  online route), and tests in `tests/core/test_prompt.py`, `test_memory_recall.py` and `test_memory_facts.py`

**Interfaces / rules:**
- The memory block begins with exactly `### What you know about them (the only true things you know):` and ends with
  `### End`. The reply-rules line is `### Reply rules: <rule>`, using the text in spec §4.2.
- `persona_local.md` is at most 180 words. `style_examples.md` starts with "Made-up examples of your style. They never
  happened. Never mention them." and has 6–8 exchanges with no user-specific facts.
- The router decides the route before the prompt is built (`Router.route(text)`). The prompt uses the local or online
  persona to match.
- N1: an about-me query yields eligible facts first, then fills to 8. "tell me what you remember about my sister's
  wedding" is not about-me.
- Negations: `{"no", "not", "never", "nor"}` and tokens ending in "n't" are removed from STOPWORDS. Test that "The user
  is vegetarian" and "The user is not vegetarian" are both stored.

**Steps:**
- [ ] Tests for each rule. The prompt tests assert the delimiters and that style examples never sit inside the memory
  block. RED, then GREEN.
