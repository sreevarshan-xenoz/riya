# Riya v0.3 "Her eyes" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Riya glances at the user's active window, keeps short notes, leans toward what they're doing, answers
questions about the screen, and covers her eyes on request. Screenshots never touch disk.

**Architecture:**
- A new subpackage `riya/core/eyes/` with three parts: `capture.py` (Windows window info and in-memory grab), `policy.py`
  (pure: when a glance is allowed or wanted) and `see.py` (vision requests, note parsing, the screen-question detector).
- Memory gains a `glances` table (schema v2).
- The engine runs glances in `tick` and handles screen questions in `reply`.
- The protocol gains `look`, `eyes`, `dont_look`, `glance_delete` and `memories.glances`.
- The body leans by side, covers her eyes, and gets an Eyes settings section.

**Spec:** `docs/superpowers/specs/2026-10-18-riya-v0.3-her-eyes-design.md`

## Global Constraints
- A screenshot never touches disk: no file writes anywhere in the capture or see path. Tests patch file APIs to fail.
- No capture is ever taken while `dont_look` is on, eyes are disabled, the window is denylisted or Riya's own, presence
  isn't focused or talking, the online model is unavailable, or the daily cap is reached.
- Default denylist regexes (case-insensitive):
  - Title: `password|1password|bitwarden|keepass|lastpass|bank|banking|paypal|upi|net ?banking|credit card|inprivate|incognito|private browsing|windows security|credential|sign in to|login|sign in|sign-in|log in|log-in`
  - Process: `keepass.*|1password.*|bitwarden.*|credentialuibroker|dashlane.*|nordpass.*|enpass.*|roboform.*|keeper.*|proton ?pass.*`
- Defaults: `glance_daily_cap` 150, `glance_min_gap_s` 45, settle 4 s, re-glance after 300 s if the 64×36 grayscale MAD
  is above 6/255, notes kept 7 days, JPEG long side ≤ 1280 at quality 70.
- The vision note is JSON only, `{app, activity ≤12 words, details ≤30 words, notable|null}`.
- Hotkeys: don't-look `Control+Alt+H`, falling back to `Control+Alt+F10`.
- Default online model alias: `gemini-flash-latest` (from v0.2).
- Core tests stay offline. `mss` is imported lazily inside `capture.py`'s grab, and `requirements-riya.txt` gains `mss`.
- Everything green stays green.

## Review Focus
1. **The foreground window is on a second monitor or partly off-screen.** The rect is clamped to that window's monitor.
2. **The title is in another language or has emoji.** The denylist and notes handle Unicode.
3. **Don't-look toggled mid-glance.** A capture already in flight is discarded and never sent.
4. **The DB upgrades from schema v1.** An existing riya.db migrates without data loss.
5. **The online model is over quota.** Glances back off for 30 min, and chat still falls back to local.

### Task 1: Capture (Windows foreground window → JPEG bytes)
**Files:**
- Create: `riya/core/eyes/__init__.py`, `riya/core/eyes/capture.py`, `tests/core/test_eyes_capture.py`
- Modify: `requirements-riya.txt`

**Interfaces:**
- `@dataclass WindowInfo(hwnd: int, title: str, process: str, rect: tuple[int, int, int, int], monitor: tuple[int, int, int, int], minimized: bool, is_riya: bool)`
- `class WindowSource(Protocol): def foreground(self) -> WindowInfo | None`
- `WindowsWindowSource` uses ctypes:
  - `GetForegroundWindow`, `GetWindowTextW`, `GetWindowThreadProcessId`, `QueryFullProcessImageNameW`
  - `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS=9)`
  - `MonitorFromWindow` and `GetMonitorInfoW`
  - `IsIconic`
  - `is_riya` is true when the process image path is under `<repo>/body/node_modules/electron`, or the process is
    electron.exe and the title starts with "Riya".
- `FakeWindowSource(info)` for tests.
- `set_dpi_awareness() -> None` calls `SetProcessDpiAwarenessContext(-4)`, falling back to `SetProcessDpiAwareness(2)`.
  It's idempotent and never raises.
- `grab_jpeg(info, max_side=1280, quality=70) -> bytes` uses mss (lazy) for the region `clamp(info.rect, info.monitor)`
  and encodes a JPEG in memory with Pillow. It returns `b""` for an empty region.
- `thumb(jpeg: bytes) -> bytes` gives 64×36 grayscale raw bytes. `mad(a: bytes, b: bytes) -> float` gives the mean
  absolute difference in 0..1.

**Tests:**
- Clamp math, including a rect partly off its monitor.
- Fake grab path: monkeypatch an mss stub returning a small RGB buffer, and assert JPEG magic bytes.
- No disk: patch `builtins.open`, `PIL.Image.Image.save` with a path and `os.replace` to raise on file paths, and grab
  succeeds.
- `thumb` and `mad`.
- On Windows only (skip elsewhere): `WindowsWindowSource().foreground()` returns something or None without raising.

### Task 2: Glance policy (pure)
**Files:**
- Create: `riya/core/eyes/policy.py`, `tests/core/test_eyes_policy.py`

**Interfaces:**
- `DENY_TITLES` and `DENY_PROCESSES` (the defaults above).
- `denied(info, extra_titles, extra_processes) -> bool`.
- `class GlancePolicy(clock, *, cap=150, min_gap_s=45, settle_s=4, refresh_s=300, mad_threshold=6/255)`:
  - `allowed(*, info, presence, eyes_enabled, dont_look, online_ok, extra_titles=(), extra_processes=()) -> str | None`
    returns None when allowed, otherwise a reason string.
  - `wanted(info, thumb: bytes | None) -> bool` covers a stable window change (settle) or refresh with MAD above the
    threshold.
  - `record(info, thumb)` and `backoff(seconds)`.
  - `glances_today() -> int`, which resets at local midnight.
- Screen questions call `allowed(...)` with `force=True`, which bypasses only `min_gap`.

**Tests:** a table of every allow and deny reason, settle timing, the refresh MAD rule, the cap reset at local
midnight, backoff, and Unicode or emoji titles.

### Task 3: Seeing (vision requests, note parsing, screen questions)
**Files:**
- Create: `riya/core/eyes/see.py`, `tests/core/test_eyes_see.py`
- Modify: `riya/core/models.py` (message `content` may be a list of parts, sent as-is; add a test)

**Interfaces:**
- `NOTE_PROMPT: str`.
- `vision_messages(jpeg: bytes, text: str, system: str | None = None) -> list[dict]` uses content parts
  `[{"type":"text",...},{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}]`.
- `@dataclass GlanceNote(app, activity, details, notable)` and `parse_note(text) -> GlanceNote | None`, which takes the
  outermost JSON object and clips fields to the word limits.
- `is_screen_question(text) -> bool`. These count: "what's wrong with this", "can you see this error", "what am I
  looking at", "read this", "look at my screen". These don't: "what's wrong with you", "this weekend was fun".
- `describe(model, jpeg) -> GlanceNote | None` never raises; `ModelUnavailable` returns None.

### Task 4: Memory, engine, protocol and settings integration
**Files:**
- Modify:
  - `riya/core/store.py` (schema v2: `glances(id, at, app, title, activity, details, notable)`, a migration from v1)
  - `riya/core/memory.py` (`add_glance`, `recent_glances(n)`, `delete_glance(id)`, purge after 7 days, list for the
    memories message)
  - `riya/core/settings.py` (`eyes_enabled`, `glance_daily_cap`, `glance_min_gap_s`, `eyes_deny_titles`,
    `eyes_deny_processes`, `dont_look`, all validated)
  - `riya/core/protocol.py` (`Look`, `EyesMsg`, `DontLook`, `GlanceDelete`, `memories.glances`; regenerate the schema
    with `--write`)
  - `riya/core/prompt.py` (a `### What they're doing now:` line and up to 3 recent notes, outside the memory block)
  - `riya/core/engine.py` (glance step in `_tick`, the screen-question path in `reply`, bid reason from the latest note,
    consolidation gets the chunk's notes as context, emits `look` and `eyes`)
  - `riya/core/__main__.py` (build `WindowsWindowSource` plus `set_dpi_awareness` on Windows, `FakeWindowSource(None)`
    elsewhere)
  - Body test fixtures if the schema test needs them
- Tests: `tests/core/test_eyes_engine.py`, plus updates

**Behaviour:**
- **Glance step.** Every tick:
  - Read the foreground window. Compute and emit `look.side` from the window centre relative to the buddy position. If
    the body's position is unknown, use the screen centre: left of centre gives "left", the middle 20% gives "center".
  - Emit `look` only when the side or `watching` changes.
  - If `policy.allowed` and `policy.wanted` both pass, grab and run `describe` in a worker thread so the tick isn't
    blocked. Store the note, then `record`.
  - On `ModelUnavailable` or a 429, back off 1800 s.
  - If `dont_look` turned on before the result returned, discard it (Review Focus 3).
- **Screen question.** On `reply`, if `is_screen_question` and the forced policy check allows, grab and send to the
  online model via `vision_messages` with her full prompt. Shaping (v0.2) still applies. If not allowed, the situation
  tells her why ("you can't see right now: <reason>"), so she answers honestly.
- **Don't look.** A `DontLook` message sets the setting, emits `eyes` plus an `expression` override `covering_eyes`
  while on, and records in KV.
- **Migration.** A v1 DB with facts opens as v2 with the facts intact (test).

### Task 5: Body (lean side, don't-look, Eyes settings, glance notes)
**Files:**
- Modify:
  - `body/src/sprite-logic.js` (`leanFor({presence, curiosity, look})`: when `look.watching`, lean toward `look.side`,
    left giving -6° and -12 px, right giving +6° and +12 px; center or null falls back to the old behaviour)
  - `body/src/main-logic.js` (`TALK_HOTKEYS`-style `DONT_LOOK_HOTKEYS = ["Control+Alt+H", "Control+Alt+F10"]` via
    `pickHotkey`)
  - `body/main.js` (register the hotkey and send `dont_look {on: !current}`; tray "Don't look" checkbox)
  - `body/renderer.js` (`covering_eyes` comes from the core's expression; no extra logic)
  - `body/settings.html`, `settings.js`, `src/settings-logic.js` (an Eyes section: enable, cap, min gap, deny patterns
    as textarea lines validated as regexes, today's count from `eyes`, a glance notes list with delete)
  - Fixtures for the new messages
- Tests: lean side, hotkey fallback, regex validation, glance list rendering helpers.

### Task 6: Live eyes check
**Files:** `evaluation/eyes_check.py`
- With `RIYA_ONLINE_API_KEY`: open Notepad with known text via `subprocess` (`notepad.exe` plus a temp `.txt` with
  "Riya eyes check 4721"), focus it, take one glance, ask "what does this say?", and print the note and answer. Pass if
  "4721" appears. Close Notepad and delete the temp file.
- Without a key: print "skipped (no online key)" and exit 0.
- Not part of pytest.
