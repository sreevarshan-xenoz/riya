# Riya v0.7 "Ready for you" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Riya can be set up from inside herself: a first-run welcome in her voice, a Settings → Health page that shows
what works and fixes what doesn't, and an online key stored outside the repo that never leaves the core.

**Architecture:**
- Three new core modules, each pure behind injected seams:
  - `riya/core/secrets.py`: the key file, its precedence over `.env`, the mask and log redaction.
  - `riya/core/health.py`: ten read-only checks, each in its own thread with a 5 s timeout.
  - `riya/core/setup.py`: the allow-listed actions, the confirm/nonce store and the action worker.
- The engine wires them to four new body → core and four new core → body messages. It never runs a check or an action
  under the core lock, and `reply()` never reaches setup.
- The body gets a Health section with a confirm modal (`src/health-logic.js`) and a welcome window
  (`welcome.html`, `welcome.js`, `src/welcome-logic.js`). `evaluation/health_check.py` prints the table from a
  running core.

**Tech Stack:** Python 3.12 stdlib (`threading`, `logging`, `sqlite3` JSON1, `urllib`), pydantic, Pillow (the test
picture), pytest; Electron 33 with `node --test` and Ajv; `websockets.sync` for the live check.

**Spec:** `docs/superpowers/specs/2026-10-19-riya-v0.7-ready-for-you-design.md` (§4.4 is binding).

## Global Constraints
- **Timeouts:** every Health check has a 5 s timeout (`CHECK_TIMEOUT_S = 5.0`). The body refreshes Health on open and
  every 30 s while the page is visible (`REFRESH_MS = 30000`). A nonce expires 60 s after it was issued
  (`NONCE_TTL_S = 60`; valid while `now - issued_at < 60`) and is single-use.
- **The key:** after trimming outer whitespace it is non-empty, at most 200 characters, with no whitespace or control
  characters (any `str.isspace()` character or Unicode category `C*`). `mask(key)` is `"••••" + key[-4:]` (a key
  under 8 characters masks to `"••••"`).
- **The key file:** `%LOCALAPPDATA%\Riya\secrets.env`, one line `RIYA_ONLINE_API_KEY=<key>\n`, written with
  `install_hooks.write_atomic`. It is never in the repo; `.gitignore` gains `secrets.env`.
- **Precedence (§4.4.3):** a key in secrets.env beats the repo `.env` and the process environment. `online_key_clear`
  removes only the secrets.env key. A `.env` key shows "set via .env (edit that file to remove it)" and can't be
  cleared from Riya. Setting or clearing rebuilds both the online and the vision model.
- **The key never leaves the core** except as the mask: not in a message, log line, transcript, memory, KV row,
  action-log row, error, git or test fixture.
- **Confirm-gated** (they need `setup_confirm` → `setup_action {nonce, yes}`): `online_test`, `eyes_test`,
  `hooks_connect`, `hooks_disconnect`, kept in that order as `CONFIRM_GATED`.
- **Plain-click** (they run straight from `setup_request`, with no nonce): `online_key_set`, `online_key_clear`,
  `voice_sample`, `voice_choose`, `mic_check`, `autostart`, `onboarding_done`.
- **The eye test** sends only `riya/core/assets/eyes_test.png` (the text "Riya eye test 42") and passes when the answer
  contains "42". It never captures a window.
- **Details:** every `HealthItem.detail` and `setup_result.detail` is one line of at most 120 characters
  (`DETAIL_MAX = 120`).
- **Confirm text** for both hooks actions ends with "Restart Claude Code (and open a new terminal) afterwards."
- **Nothing outward-facing is automatic:** no setup action runs on startup, from the model, from a tool call, from a
  hook payload or from any other path than a body `setup_request` / `setup_action` / `onboarding_done`.
- **Tests:**
  - They never open apps, URLs or windows and never use the network.
  - They never touch the real `~/.claude/settings.json` or the real `%LOCALAPPDATA%\Riya`. The new
    `tests/conftest.py` (Task 1) redirects every default path to `tmp_path`.
  - Every path is injectable.
- **Never run the Claude Code hooks installer for real**, and never `setx`. The builder only runs it on temp paths
  with a fake runner.
- **Protocol schema:** `python -m riya.core.protocol --write docs/protocol.schema.json`, never a shell redirect.
- **Commit trailer:** end every commit message with exactly these two lines:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: <session-link>`.
- **Everything green stays green:** `.venv\Scripts\python -m pytest -q` and `cd body && npm test`, after every task.

## Review Focus
1. **The key leaking.** A canary key set through the body never shows up in an emitted message, a log record (from any
   logger, including one with `propagate=False`), a transcript, a fact, a KV row, the action log, an error or a
   protocol parse error. Only its mask appears. Tests: Task 1 `test_redaction_scrubs_every_logger`, Task 4
   `test_the_key_never_leaves_the_core` and `test_a_bad_setup_request_never_echoes_its_args`, Task 5
   `test_submitKey_sends_once_and_clears_the_field`.
2. **An outward action without a confirm, or with a stale or reused nonce.** `hooks_connect` only runs after a
   `setup_action yes` with a fresh nonce, exactly once, on the temp path. A reused nonce, one 60 s old or a No runs
   nothing. Model replies, tool calls and hook payloads never reach setup. Tests: Task 3
   `test_nonces_are_single_use_and_expire_at_60_s`, Task 4
   `test_hooks_connect_needs_a_confirm_and_runs_once_on_temp_paths`, `test_nothing_outward_runs_without_a_confirm` and
   `test_model_tools_and_hooks_never_reach_setup`.
3. **A Health check blocking the core or hanging.** A check that sleeps forever reports "No answer within 5 s." while
   the others report. `health_get` returns at once and the health message arrives while the core lock is held.
   Tests: Task 2 `test_a_hung_check_times_out_and_the_rest_still_report`, Task 4
   `test_health_runs_off_the_core_lock`.
4. **Existing users nagged by the welcome, or new users skipping it.**
   - A v1–v4 database opens with `onboarded=true`; a brand-new one has `false`, and stays `false` on its next open
     until `onboarding_done`.
   - The body opens the welcome only for `onboarded === false`, once per session.
   - Tests: Task 4 `test_existing_users_are_onboarded_new_ones_are_not`, Task 6
     `shouldOpenWelcome only for onboarded false, once`.
5. **`.env` vs secrets.env precedence and Clear.**
   - A saved key wins over `.env` and the environment.
   - Clear falls back to the `.env` key, refuses to clear a `.env` key, and rebuilds both models every time.
   - Tests: Task 1 `test_key_precedence_and_clear`, Task 4 `test_key_set_and_clear_rebuild_both_models`.

**Interfaces:** Produces, in `riya/core/secrets.py` (always imported as `from riya.core import secrets as keystore`,
never as a bare `secrets`):
- **Constants:**
  - `KEY_VAR = "RIYA_ONLINE_API_KEY"`, `MAX_KEY_LEN = 200`, `MASK = "••••"`, `REDACTED = "[redacted key]"`.
  - `REDACT_MIN = 8`: shorter values are never scrubbed, since a test key like `"k"` would shred every log line.
  - `Source = Literal["app", ".env", "env"]`.
- **`class InvalidKey(ValueError)`** with exactly these messages, which never contain the input: `EMPTY = "The key is
  empty."`, `TOO_LONG = "The key is longer than 200 characters."`, `BAD_CHARS = "The key can't contain spaces or control
  characters."`.
- **File and mask functions:**
  - `default_path() -> Path`: `Path(os.environ.get("LOCALAPPDATA") or Path.home() / "AppData" / "Local") / "Riya" /
    "secrets.env"`, read at call time.
  - `validate(raw: str) -> str`: strips the ends, then applies the rules.
  - `mask(key: str | None) -> str | None`.
  - `load(path: Path) -> str | None`. A missing, unreadable or invalid file → None, logged without its value.
  - `save(key: str, path: Path) -> str`: returns the validated key and remembers it for redaction.
  - `clear(path: Path) -> bool`: True when a file was removed.
- **Redaction:**
  - `remember(key: str | None) -> None` adds to a lock-guarded module set. `scrub(text: str) -> str` replaces every
    remembered key of length ≥ `REDACT_MIN` with `REDACTED`.
  - `class RedactFilter(logging.Filter)`: `filter(record)` always returns True. It sets `record.msg =
    scrub(record.getMessage())` and `record.args = None`. When `exc_info` is set, it sets `record.exc_text` to the
    scrubbed `logging.Formatter().formatException(exc_info)`. It also scrubs `stack_info`.
  - `install_redaction(root: logging.Logger | None = None) -> RedactFilter`: idempotent. It adds the filter to the
    root logger and to each of its handlers. It also wraps `logging.getLogRecordFactory()`, so every record from any
    logger passes through the filter when created; this covers uvicorn's own handlers and `propagate=False` loggers.
  - `uninstall_redaction() -> None`: restores the factory and removes the filter (for tests).
- **`@dataclass(frozen=True) KeyInfo(mask: str | None, source: Source | None)`**, with the property
  `clearable -> bool` (`source == "app"`).
- **`class OnlineKey(path: Path, base: str | None, base_source: Literal[".env", "env"] | None)`:**
  - `at_start(environ: Mapping[str, str], had_env_key: bool, path: Path) -> OnlineKey` (classmethod). `base` is the
    stripped `environ[KEY_VAR]` or None. `base_source` is `"env"` when `had_env_key`, else `".env"` when `base` is set,
    else None. It remembers `base` and `load(path)` for redaction.
  - `current() -> tuple[str | None, Source | None]`: `(load(path), "app")` when the file has a key, else
    `(base, base_source)`.
  - `info() -> KeyInfo`.
  - `set(raw: str) -> str`: `save`; raises `InvalidKey` or `OSError`.
  - `clear() -> bool`: `clear(path)`.
  - `env(environ: Mapping[str, str]) -> dict[str, str]`: a copy with `KEY_VAR` set to `current()[0]`, or without
    `KEY_VAR` when there is none.
- **In `models.py`:** `VISION_TIMEOUT_S = 20.0` and `online_pair(env: Mapping[str, str]) ->
  tuple[OpenAICompatModel | None, OpenAICompatModel | None]`, which returns `(load_online_from_env(env),
