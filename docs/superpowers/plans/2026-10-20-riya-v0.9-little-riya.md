# Riya v0.9 "Little Riya" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Buddy mode becomes a living desktop pet. Little Riya walks, idles, sits, sleeps, can be dragged and dropped,
reacts live to Claude Code activity (tool bubbles, think, wave, confetti, oops), and a click on her brings the agent's
terminal to the front.

**Architecture:**
- **Core (`riya/agents/`, `riya/core/`):**
  - `hub.py` turns hook payloads into short, redacted activity labels and rate-limits them per session.
  - The engine emits `agent_activity` from a lock-free step in `tick()`, so her own replies never delay a reaction.
    It also emits an on-change `presence` message.
  - New `riya/agents/peer.py`:
    - The hook handler records each session's peer PID, found synchronously through `GetExtendedTcpTable`.
    - At click time, `focus_agent` resolves that PID to a top-level window and answers `agent_window`.
    - The core never focuses anything. Every Windows call sits behind an injectable `PeerOS`.
- **Body (`body/`):**
  - `src/pet-logic.js` is pure. It holds the state machine, kinematics, gates, reaction table, sizing and transforms,
    with seeded timers.
  - `main.js` owns one `Pet`. It moves the window at 20 Hz only while she walks or falls, reads idle time from
    `powerMonitor`, and turns a click into `win.focus()` → `focus_agent` → `agent_window` → a short-lived
    `python -m riya.agents.peer focus <hwnd>`.
  - `renderer.js` draws poses, the activity bubble and a small effects canvas (`src/effects-logic.js`).

**Tech Stack:** Python 3.12 stdlib (`ctypes`, `shlex`, `dataclasses`), pydantic, FastAPI and pytest. Electron 33 with
`node --test` and ajv.

**Spec:** `docs/superpowers/specs/2026-10-20-riya-v0.9-little-riya-design.md`. §4.1 (the builder-check decisions) is
binding.

## Global Constraints
- **Walking:**
  - She walks in bursts of 3–10 s every 40–180 s, at 60–90 DIP/s, facing her direction, along the bottom of the work
    area, just above the taskbar.
  - The window moves at 20 Hz during walks and falls, and not at all otherwise.
  - She walks only when the user has been idle for 30 s or more (`pet_walks_when = "idle"`, the default). She never
    walks while gaming, in full screen, in quiet hours, under reduced motion, or with presence unknown. Agent activity
    never makes her walk.
  - The dev override `RIYA_PET_FORCE_WALK=1` (for `pet_cpu`) skips only the idle threshold and the unknown-presence
    check. Gaming, away, quiet hours and reduced motion still keep her from walking.
  - A walk or a due walk always sees the user's idle time as of that step, never a sample seconds old.
- **CPU:** at most 3% while walking and at most 1% while idle, measured by `evaluation/pet_cpu.py`.
- **Sleep:** she sleeps when presence is "away", in quiet hours, or after 10 minutes with no user input and no agent
  event. Any agent event wakes her to sit or react, except while away.
- **Bubbles:**
  - At most 40 chars, built only from a tool name plus a file basename or a command's first word, through `redact`.
  - A basename or first word that contains `sk-`, `ghp_`, `xox`, `AKIA`, `Bearer`, `=` (case-insensitive) or a run
    of 20+ alphanumeric chars is never shown. It reads "a file" or "a command" instead.
  - At most 1 per 1.5 s per session; the latest one wins.
  - Never spoken.
- **Size:**
  - `pet_scale` defaults to 0.6, with a range of 0.4–1.0.
  - Width is `max(sprite width × scale, 240 DIP)`. Height is `sprite height × scale + 80 DIP` of bubble room `+ 24 DIP`
    of effects headroom.
  - Every move is a `setBounds` with that fixed width and height. Her feet rest on `workArea.bottom`.
- **Rare surprise:** 1 finish in 50 (a spin or a heart).
- **The reaction table** (spec §2.2, verbatim):

  | Agent event | What she does |
  |---|---|
  | PreToolUse | An activity bubble with a short label: "editing engine.py", "running tests", "reading the spec", "searching the code", "browsing", "asking a helper". The label comes from the tool name and a safe summary of the input: a file basename, the first word of a command, never full arguments, passed through `redact`. |
  | UserPromptSubmit | A "thinking" pose. |
  | PermissionRequest | She waves and shows "needs you!" with the tool summary. |
  | Stop | A happy pose with a small confetti burst. |
  | Tool failure | An "oops" pose: worried, with a sweat drop. |
  | StopFailure | A sad pose. |
  | SubagentStop | A tiny "helper done" sparkle. |
- **Focus:**
  - Only a click on her pixels starts a focus. The core resolves the hwnd at click time, never at hook time.
  - The helper does `ShowWindow(SW_RESTORE)` when the window is minimised, then `SetForegroundWindow`.
  - With no window found she opens the agents list.
- **The hook receiver:** it still answers an empty 200 at once for every event, PreToolUse included.
- **Tests:**
  - They never launch Electron, the core or llama-server, and never use the network.
  - They never call real Windows focus, process or TCP APIs. Everything goes through `PeerOS` / `user32` injection, and
    the conftests patch the runner's real `default_peer_os`.
- **Never run the Claude Code hooks installer** against real settings, and never `setx`. Installer tests use temp paths
  only.
- **Protocol schema:** regenerate with `.venv\Scripts\python -m riya.core.protocol --write docs/protocol.schema.json`.
- **No HTML sinks:** labels, titles and every hook-derived string reach the DOM through `textContent` only.
- **Commit trailer** (the project's implementer contract): end every commit message with exactly these two lines:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01BiCkE9KiCaYfkY6JzGzsZx`.
- **Everything green stays green:** after every task, `.venv\Scripts\python -m pytest -q` and `cd body && npm test`
  pass.

## Spec ambiguities resolved here (binding for this plan)
1. **`pet_walks_when`:**
   - §4.1.4 wins over §4: the values are `"idle"` (default: walk at user idle ≥ 30 s) and `"always_but_focus"` (walk at
     idle ≥ 5 s).
   - `breaks_only` isn't a value.
2. **The TCP row:**
   - §4.1.5's "local port 8766, remote = `request.client.port`" is the server's own row, whose PID is the core.
   - The owner is the client-side row: local port `request.client.port`, remote port 8766, with our own PID refused.
3. **Sprite size units:** "sprite height" at scale 1.0 is a reference 400 DIP tall, with the width from the pack's
   aspect, whatever the pack's canvas pixels. At 0.6 the window is 240 × 344 DIP.
4. **`pet_enabled` false is exactly v0.8 buddy:** the 300×520 window, no walking, no bubbles, no click-to-jump. Pet
   sizing applies only with the pet on.
5. **`reduced_motion`:**
   - `"system"` (default, follows the renderer's `matchMedia`), `"on"` or `"off"`.
   - Under reduced motion: no walk, no fall (a drop stays where it is), no oscillating motion and no effects. The pose
     and the bubble still show.
6. **Which reactions are "big":**
   - Confetti, the heart and the spin need not-focused: presence known and not gaming, not quiet, no reduced motion, and
     idle ≥ 30 s.
   - Pose, bubble, sparkle, sweat and wave always show.
   - While gaming or away nothing shows (the badge still counts).
7. **Bubble-only kinds don't interrupt:** edit, run, read, search, web and delegate never stop a walk. The pose kinds
   stop a walk and queue (at most 3).
8. **Sleep after 10 minutes:** no user input for 600 s and no agent event for 600 s.
   - Quiet hours: she sleeps, wakes to react, then sleeps again.
   - "Go to sleep" from the menu wakes only on a pose reaction, a click or a grab.
9. **The click target:**
   - The first Claude session needing attention; else the session of the latest activity, if under 10 minutes old and
     not ended.
   - With neither, a click is a happy "poke" and nothing is sent. "The agents list" is Settings scrolled to its Agents
     section.
   - "Not found" (§4.1.5) also covers no answer: with the core disconnected at click time she opens the list at once,
     and when `FOCUS_WAIT_MS` passes with no `agent_window` she opens it then.
10. **The window walk:**
    - The chain stops at explorer and the system processes.
    - A chain process's own console host (`conhost.exe` / `OpenConsole.exe` child) counts as its window owner.
    - "Most recently active" means first in `EnumWindows` z-order. Cloaked windows don't count.
11. **The peer cache:**
    - A `SessionStart` forces a fresh PID lookup (a resumed session in a new process).
    - Cached PIDs are otherwise kept until a miss, as §4.1.5 says.
12. **The latency path:**
    - `agent_activity` is produced from a second inbox drained before the core lock in `tick()`, so a long reply never
      delays a reaction.
    - The hub itself only treats PreToolUse as a liveness event (unknown → busy).
13. **`presence` isn't added to hello:** hello's `state` already carries it, so the hello-order pin stays.
    `agent_activity`, `presence` and `agent_window` are never replayed to new windows.
14. **Labels:** an unknown tool is "using a tool". A command's first word skips `VAR=value` prefixes and must match
    `[A-Za-z0-9._+-]{1,24}`, else it is "running a command". The test-runner patterns give "running tests".
    `redact`'s `\b` anchors miss a marker glued to a word (`Xsk-ant-…`), so a basename or first word that looks
    secret (Global Constraints, Bubbles) is masked to "a file" / "a command" before it can reach a label.
15. **Her position:** it's saved (`buddy_position`) when a walk ends, when a fall lands and when a drop needs no fall,
    so she reopens where she sat. A click never saves. `BUDDY_HALF_W` (the look side) stays an approximation.
16. **Facing:** +1 is the art's natural orientation. -1 mirrors `#pet`, and the hit mask is mirrored to match.
17. **Landing:** as spec §2.1 says, a fall lands with a squash and then she stands (`idle`). A drop at the floor, or
    under reduced motion, goes straight to `idle`.

## Review Focus
1. **Walking or big reactions distracting during focus or gaming.**
   - She never walks with idle < 30 s (`idle` mode), while gaming or full screen, in quiet hours, under reduced motion,
     or with presence unknown.
   - Confetti and the surprise need the same "not focused" gate.
   - While gaming nothing shows at all.
   - Tests:
     - Task 4: `gates follow the table` (including the `forceWalk` rows), `a due walk never starts while focused,
       gaming, quiet, reduced or unknown` and `while gaming a reaction shows nothing; while focused a finish is pose and
       bubble only`.
     - Task 5: `presence comes from both state and presence messages and is forgotten on disconnect` and `the pet
       steps at once on every feed and reads idle fresh`.
2. **A bubble leaking a secret or long text.**
   - Only a basename or a command's first word ever reaches a label, after `redact`, with at most 40 chars.
   - The protocol and the body clip again.
   - Tests:
     - Task 1: `test_labels_never_leak_secrets_or_long_text`, `test_secret_looking_names_become_a_file_or_a_command`
       and `test_labels_fuzz_stay_short_and_clean`.
     - Task 3: `test_agent_activity_label_is_capped_at_40`.
     - Task 4: `bubbleText clips to 40`.
3. **Click-to-jump focusing the wrong app, or focusing without a click.**
   - Windows come only from the agent's own process chain. The walk stops at explorer and system processes.
   - A title match wins, else the first window in z-order.
   - The core never focuses. Main spawns the helper only for its own pending click, within 3 s.
   - Renderers can't send `focus_agent`.
   - Tests:
     - Task 2: `test_window_choice_stays_in_the_agents_chain` and `test_focus_restores_then_foregrounds_only_a_visible_window`.
     - Task 3: `test_nothing_focuses_without_a_click`.
     - Task 5: `a focus only follows its own fresh click`, `renderers can never send focus_agent` and `a click with no
       answer opens the agents list`.
4. **CPU burn while walking.**
   - Main ticks only in walk and fall, at 20 Hz. Idle wakes are seconds apart.
   - The effects timer stops when the effect ends.
   - CPU is measured manually.
   - Tests:
     - Task 4: `ticks only while walking or falling, and idle wakes are at least 1 s apart`.
     - Task 6: `effects end on time and draw nothing after`.
     - Task 7: `test_cpu_percent_and_verdict`.
5. **A walk leaving the work area or covering the taskbar** (mixed DPI, several monitors, the taskbar moving).
   - x stays in `[wa.x, wa.x + wa.width - width]` and y never passes `wa.y + wa.height - height`.
   - Coordinates are integers, with a fixed size on every move.
   - A changed work area re-clamps her at once.
   - Tests:
     - Task 4: `a walk never leaves the work area or covers the taskbar, on any monitor`, `a shrunk work area
       re-clamps her at once` and `a drop on another monitor stays there`.
     - Task 5: `moveRect is integer with a fixed size` and `main spawns the helper only through decideFocus` (the
       drop re-reads the monitor first).
