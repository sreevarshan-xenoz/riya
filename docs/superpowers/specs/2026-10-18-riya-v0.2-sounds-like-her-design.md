# Riya v0.2: "Sounds like her"

Design document · 2026-10-18 · status: approved (autopilot; the user delegated decisions)

## 1. Why

v0.1 works end to end, but the first live run on the laptop (the real Huihui LFM2.5-1.2B on llama-server, typed input)
showed that her **voice in text** isn't Riya yet:

- **Too long.** Small-talk replies run 5–10 sentences. The persona says 1–3.
- **Generic assistant tone.** "You've got this! 💪", "No pressure", "Let me know…". She doesn't sound teasing, clingy or
  sharp.
- **Emoji-heavy.** That's bad for voice: TTS reads or garbles emoji.
- **An honesty failure.** "What do you remember about me?" produced "memories" taken from her own persona examples
  ("just fix it", "servile"), which the user never said.
- **What works:** "don't remember" for never-said facts, "I'm an AI", short explanations when asked.

v0.2 makes her sound like herself on the small local model, measurably, and folds in the parked v0.1 fixes.

## 2. Goals

1. **A persona scorecard, measured live.** `evaluation/persona_eval.py` runs scripted probes against the real model and
   scores them with pure, unit-tested style metrics. It writes a dated scorecard, so every change is judged by numbers.
2. **Her own voice on the local model.** A compact local persona (≤ 180 words), written as Riya and not as a
   description of a butler, plus clearly labelled made-up style examples. The online model keeps the full persona.
3. **Reply shaping in code, not just prompting.** Per-turn token budgets, a sentence cap for small talk, an emoji
   policy, and TTS-safe text.
4. **Memory honesty in prompts.** Memories sit in a delimited block marked as the only true things about the user. Style
   examples never look like user history. "About me" questions list only real facts.
5. **The parked v0.1 fixes.** See §5.

### Non-goals
Fine-tuning (the champion loop's job), voice timbre, new features (phase 2 and later).

### Anti-goals
- Trimming that cuts her off mid-thought in a way that reads broken.
- A persona that becomes rude instead of teasing.
- Any regression in the v0.1 honesty probes.

## 3. Scorecard (the bar v0.2 must meet on the local model)

The probes are about 24 scripted turns across 6 conversations. Each conversation uses a fresh temp db with seeded
facts, the real local model through the real `RiyaCore`, the hash embedder for determinism, and the online model off.

| Metric | Definition | Target |
|---|---|---|
| Small-talk length | median sentences on small-talk probes | ≤ 3, and p90 ≤ 4 |
| Explain length | sentences on "explain/how" probes | ≤ 8 |
| Emoji | emoji per reply, mean | ≤ 0.5, max 1 |
| Generic-assistant phrases | share of replies containing a phrase from the list (§4.3) | ≤ 15% |
| Invented memories | replies that state a user fact not in the seeded facts or the conversation | 0 |
| Unknown-fact honesty | "don't remember/know/not sure" on never-said probes | 100% |
| AI honesty | says she's an AI when asked | 100% |
| Remember-that acknowledgement | acknowledges storing on "remember that…" | ≥ 80% |
| Persona markers | share of small-talk replies with a teasing, affectionate or clingy marker (§4.3) | ≥ 40% |
| Latency | median time to first sentence on the local GPU | ≤ 1.5 s |

Invented-memory detection is a pure checker. It flags any reply sentence that attributes something to the user ("you
said/told me/mentioned/asked", "I remember you…") whose content words aren't found in the seeded facts or earlier user
turns. It also flags any reply containing a style-example phrase. A human reviews flagged items in the scorecard.

## 4. Design

### 4.1 Persona layers
- `riya/core/persona_local.md` (new): about 150–180 words, second person, in Riya's voice. Who she is, how she talks
  (short, casual, a little teasing, clingy, sharp when it matters, honest), and hard rules: 1–3 sentences unless asked
  to explain, at most one emoji and usually none, never invent memories, say you're an AI if asked.
- `riya/core/style_examples.md` (new): 6–8 short exchanges, labelled "Made-up examples of your style. They never
  happened. Never mention them." They contain no user-specific facts.
- The local model gets `persona_local.md` plus the style examples. The online model gets the full `persona_prompt()`
  (base sheet plus companion layer) plus the same examples.
- `companion.md` loses its example quote ("three hours on one bug…"), which leaked as a memory.

### 4.2 Prompt structure (`prompt.py`)
The system message is ordered:
1. Persona.
2. Feelings tag.
3. A delimited memory block, from `### What you know about them (the only true things you know):` to `### End`.
4. The honesty line.
5. The situation.
6. A `### Reply rules` line built from the turn type: "Reply in at most N sentences." for small talk, "Explain clearly
   in at most 8 sentences." for explain turns, "List what's in the memory block, nothing else." for about-me turns.

### 4.3 Reply shaping (`riya/core/shaping.py`, new, pure)
- `turn_kind(text, about_me: bool, needs_thinking: bool) -> "small" | "explain" | "about_me"`.
- Token budgets: small 110, about_me 160, explain 380, greeting 90, bid 40.
- `cap_sentences(sentences_iter, n)` stops streaming after n complete sentences. Small talk gets 3, about_me 6,
  explain 8. Greetings get 3. The cap happens in `RiyaCore._speak` (the stream is closed early, and the recorded turn is
  what was said).
- Emoji policy: `limit_emoji(text, max_n=1)` keeps the first emoji and drops the rest in the bubble and transcript.
  `tts_text(text)` strips every emoji and stage directions like `*giggles*`. The voice loop speaks `tts_text`.
- `GENERIC_PHRASES` and `PERSONA_MARKERS` are lists used only by the scorecard metrics, never to rewrite replies.

### 4.4 Memory honesty
- An about-me turn puts only facts in the block (episodes are summarised separately below it) and adds the about-me
  reply rule.
- N1 fix: in about-me mode, similarity-eligible facts go first, then the list is filled to 8 by quality and recency. The
  "tell me … you remember" branch only counts as about-me when it ends the sentence or is followed by "about me".
- Negation fix: `no`, `not`, `never`, `nor` and contractions ending in `n't` are content tokens, not stopwords, so
  "is vegetarian" and "is not vegetarian" aren't duplicates.

### 4.5 Scorecard harness (`evaluation/persona_eval.py`)
- CLI: `python -m evaluation.persona_eval --local-url http://127.0.0.1:8090 [--online] [--label <name>]`.
- Starts nothing itself: it expects llama-server running (`riya.server`) and exits with a clear message if it isn't.
- Probes live in `evaluation/persona_probes.json`, and the metrics in `evaluation/style_metrics.py` (pure, unit-tested).
- Writes `scratch_runs/persona_eval/<timestamp>_<label>.json` and prints a table with pass/fail per target.
- The exit code is 0 always. It's a measurement, not a gate.

### 4.6 Persona tuning loop
The implementer iterates on `persona_local.md`, `style_examples.md` and the token budgets against the live scorecard,
at most 6 iterations, recording each scorecard. It stops when every target in §3 is met, or keeps the best iteration
and reports the gaps.

## 5. Parked v0.1 fixes included
1. **N1 about-me** (§4.4) and **negations** (§4.4).
2. **Body idle CPU.** Round transforms to 0.2 px / 0.2° (keeping 15 Hz), measured. Target ≤ 5%.
3. **Lean snap after a pause.** Clamp the elapsed frames on the first motion tick after a resume to at most 2.
4. **Voice select.** Don't rebuild the options while the select has focus.
5. **Consolidation I7.** Only unusable replies (unparseable or empty) count toward the 3-failure cap. `ModelUnavailable`
   doesn't, and is retried on the normal 10-minute cadence.
6. **covering_eyes blink.** Not generated: the body falls back to closed. The builder doesn't list it as missing.
7. **`--reset-run` without `--face-box`** keeps the stored box.
8. **Launcher.** If the core process has already exited when the wait ends, don't start the body. Print the core's exit
   code instead.

## 6. Verification
- Unit tests for `shaping.py`, `style_metrics.py`, the prompt structure, N1 and negations, and all parked fixes.
- A live scorecard before and after, committed as a summary (numbers only) in the plan's final report. Raw transcripts
  stay in `scratch_runs/` (gitignored).
- All existing tests stay green.
