# Jarvis — prototype v0

A small, efficient research model in two parts, built to train on a **free Colab T4**:

1. **Language backbone** (`jarvis/lm`): a 3:1 hybrid of **Gated DeltaNet** (linear-time recurrent memory with
   the delta rule) and **gated softmax attention** (QK-norm + sigmoid output gate), trained with **Muon** + a WSD
   schedule. Optional **BitNet b1.58** ternary linears. Pure PyTorch, so no custom kernels are needed on a T4.
2. **Affective cognitive core** (`jarvis/world`): an action-conditioned **JEPA world model** inside a body with
   drives, a homeostatic **affect core** (valence, arousal, mood, curiosity, confidence), a **global workspace**
   with a self-model, and **System 1 / System 2** control (a fast policy distilled from planning in imagination).

The affect vector feeds the LM (`HybridLM(..., affect=vec)`) so that Jarvis can speak from its actual internal state.
Design and research background: Notion pages 19–21 under *Experience-Driven Continual AI*.

## Layout

```
jarvis/lm/layers.py     Gated DeltaNet + gated linear attention (chunkwise), gated attention, BitLinear, SwiGLU
jarvis/lm/model.py      HybridLM + presets (tiny 12M / small 28M / base 92M non-embedding params)
jarvis/lm/optim.py      Muon + AdamW split, WSD schedule
jarvis/lm/data.py       stream HF dataset -> GPT-2 tokens -> uint16 memmap
jarvis/world/env.py     SurvivalGrid: body (energy, health), food vs poison fruit, lava, hidden rule shifts
jarvis/world/jepa.py    world model: latent prediction, body/death heads, self-predicted surprise, EMA target + VICReg
jarvis/world/affect.py  drives -> affect state -> behaviour modulation + emotion labels
jarvis/world/workspace.py  global workspace competition/broadcast, System 1 policy, self-model
jarvis/world/agent.py   agent loop, episodic memory, replay, latent MPC planner
train_lm.py / train_world.py / prepare_data.py / talk.py / summarize_world.py
notebooks/colab_train.ipynb   (generated by make_notebook.py)
```

## Local (CPU, for coding and tests)

```
python -m venv .venv && .venv\Scripts\activate
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install numpy pytest tiktoken datasets
python -m pytest -q
```

The tests check the chunked Gated DeltaNet and gated linear attention against a naive step-by-step recurrence,
causality of the full model, and one pass through the world-model loop.

## Colab T4

1. Get the code to Colab: push this folder to GitHub and set `REPO` in the notebook, **or** zip it as
   `jarvis.zip` into `MyDrive/jarvis/`.
2. Open `notebooks/colab_train.ipynb` in Colab and set the runtime to **T4 GPU**.
3. Run the cells. Checkpoints and logs go to `MyDrive/jarvis/runs/...`. If Colab disconnects, re-run and it resumes.

## Voice data (Notion page 23, plan step 1; CPU only)

`jarvis/voice` builds the affect-labelled dialogue set for affect-conditioned SFT. Outputs go to `data/voice/`
(git-ignored).

```
python -m jarvis.voice.build_dataset          # ED + DailyDialog -> data/voice/{empathetic_dialogues,daily_dialog}.jsonl, stats.json
python -m jarvis.voice.synth_prompts --n 20000  # teacher requests -> data/voice/synth_requests.jsonl (no API calls)
```

- `affect_map.py`: emotion label (32 EmpatheticDialogues + 7 DailyDialog + 28 GoEmotions) -> 8-dim affect vector.
  V/A/D from the NRC VAD Lexicon v2.1 (downloaded at runtime to `data/lexicons/`; non-commercial research use,
  **no redistribution**, so never commit or zip it), with a hand-written approximate fallback table when offline.
  mood = speaker's valence smoothed over prior turns; drives = small prior unless the text mentions tiredness/pain.
- `build_dataset.py`: rows `{"source","split","dialog_id","context":[{"role","text"}],"response","affect","label"}`
  from `Estwld/empathetic_dialogues_llm` (ED speaker turns) and `pixelsandpointers/better_daily_dialog`
  (every utterance, per-utterance label). The original script-based HF datasets no longer load.
- `chat.py`: `format_row(row, system)` renders `<|system|>/<|user|>/<|assistant|> ... <|end|>` text and returns
  the prompt prefix for assistant-only loss.
- `synth_prompts.py` + `persona.md`: sampled affect vectors (uniform + extremes) rendered to words
  ("fairly anxious, running low on energy, very curious") and paired with user turns, plus the Jarvis persona sheet.

## Setting Riya up

Riya (`riya/` core, `body/` Electron) sets herself up from inside the app:

- **Welcome.** On a new install she opens a short welcome in her own voice: your name, an optional Gemini key, her
  voice, how she shows up, her eyes, and your agents. Every step is skippable, and Settings opens it again any time.
- **Settings → Health.** One row per thing (local and online brain, voice, mic, look, eyes, Claude Code, Colab logs,
  memory, start with Windows), each with at most one fix button. Anything that reaches outside Riya (a key test, the
  eye test, Connect or Disconnect Claude Code) first shows exactly what it will do and runs only on your Yes.
- **Where the key lives.** A key pasted in the welcome or in Health is saved to `%LOCALAPPDATA%\Riya\secrets.env`,
  never in the repo. A key in the repo `.env` still works, but the pasted key wins; "Remove saved key" in Health
  only removes the pasted one. The key is only ever shown masked (`••••1a2b`).
- **Her memory model downloads once.** On the first start Riya fetches her memory model (bge-small, about 66 MB) into
  `%LOCALAPPDATA%\Riya\models`; until it has arrived she uses a simpler memory. With it, a personal request ("what do you
  remember about me?") gets the memories that fit. The online model doesn't get this
  extra: a personal request that routes online ("plan my week for me", "explain...") is answered without it.
- **Connect Claude Code** merges Riya's hooks into `~/.claude/settings.json` (backed up first, nothing else changed)
  and sets the `RIYA_HOOK_TOKEN` user variable. Restart Claude Code (and open a new terminal) afterwards. If your
  Claude Code settings block hooks (`disableAllHooks`, or allow-lists without Riya's entry), Health says so; Riya never
  edits those keys. The CLI does the same: `python -m riya.agents.install_hooks --print | --apply | --remove`.
- **A read-only check** of a running core's Health table, which never presses a button or changes anything:

  ```
  python -m evaluation.health_check
  ```

### Little Riya

In buddy mode Riya is a small desktop pet. She stands just above your taskbar, breathes and blinks, now and then takes a
short walk, sits, and sleeps when you're away. She reacts to what Claude Code is doing, but only with a pose and a short bubble
(never spoken, so she never breaks your focus). What you do:

- **She's on by default.** The toggle is Settings → Little Riya → "Let her walk around and react to your agents"; she
  shows up when you pick buddy mode from her tray menu. Size (0.4 to 1.0, default 0.6), Motion and "She walks" are in the
  same section. Untick the box and buddy mode is exactly the plain buddy of v0.8: no walking, no bubbles, no
  click-to-jump.
- **Connect Claude Code from Health.** Settings → Health → Connect Claude Code. It's your click: Riya never applies the
  hooks installer on her own. v0.9 adds a `PreToolUse` hook for the activity bubbles, so if you connected before, the
  row reads "Partly connected: missing PreToolUse" and offers Connect. Press it once (it shows what it will add first;
  it adds only the missing events and leaves your other hooks alone), then restart Claude Code and open a new terminal.
- **What she does** (labels come from the tool name and a file name or a command's first word, never the arguments, are
  at most 40 characters, and anything that looks like a key becomes "a file" or "a command"):

  | Claude Code | Little Riya |
  |---|---|
  | `PreToolUse` | a bubble: "editing engine.py", "reading README.md", "running tests", "running ls", "searching the code", "browsing", "asking a helper" |
  | `UserPromptSubmit` | a "thinking" pose |
  | `PermissionRequest` | she waves and shows "needs you!" with the tool |
  | `Stop` | a happy pose; after 30 s without your input (not once she's marked you away) also a small confetti burst (one finish in 50 a spin or a heart) |
  | tool failure | an "oops" pose with a sweat drop |
  | `StopFailure` | a sad pose |
  | `SubagentStop` | a tiny "helper done" sparkle |

- **Click her** to bring the agent's terminal forward: the session that needs you, or else the one that was last active
  (under 10 minutes ago). It's the terminal app's window, not a tab. If no window is found she opens the agents list
  instead, and with no agent at all a click is just a happy poke.
  If a click opens the agents list instead of bringing the terminal forward, Windows refused to hand over the focus
  (it only does so to a process the foreground app started). That fallback is by design: nothing is lost, the list
  shows the session, and you can switch to the terminal yourself.
- **Right-click her** for the menu: display mode, Don't look, Keep her still, Go to sleep, Settings, Quit. Drag her
  to pick her up; dropped above the floor she falls and lands, then stands.
- **When she stays put.** She walks only after 30 s without keyboard or mouse ("She walks" → "Any time except while you
  type" lowers that to 5 s), never while you game or run a full-screen app, and never in quiet hours. Keeping her still
  (Settings → Motion, the menu, or Windows' own reduced-motion switch) means no walking, falling or confetti; poses and
  bubbles still show. While gaming nothing shows at all. Walking is limited to the monitor she's on, along the bottom of
  the work area. With an auto-hide taskbar her floor is the bottom of the screen.
- **Walk frames (optional).** She walks with a step bob on her idle frames. For real steps make `walk_01.png` and so on
  and list them under `motions` in the pack's manifest: `colab/sprites/README.md`, step 8.
- **Two optional checks**, both manual and never part of the tests. `pet_check` posts a scripted Claude Code session
  straight to a running core and prints the five bubbles it gets back (open the body to watch her react); `pet_cpu`
  measures the body's CPU against the budget of 1% idle and 3% walking. For the walking run, start the body with
  `$env:RIYA_PET_FORCE_WALK=1` first (it skips the wait for you to be idle and the unknown-presence check, nothing else:
  gaming, away, quiet hours and reduced motion still keep her still):

  ```
  python -m evaluation.pet_check [--spawn]
  python -m evaluation.pet_cpu --mode idle|walk [--seconds 60]
  ```
